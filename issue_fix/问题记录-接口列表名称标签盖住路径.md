# 问题记录：接口列表名称列标签盖住路径（小屏 / 可编辑态）

## 现象

接口管理（`EndpointList`）列表，可编辑态（`canWrite`，多一列 42px 勾选框）下把窗口收窄
时，「名称」列末尾的标签 chip（`.tag-inline`）会溢出单元格、盖住右侧「路径」列的 URL 文本。

## 根因

`.cell-name` 是一行 flex：`Method` 徽标 + 名字 `.truncate` + `.tag-inline`。

- 这枚名字 `.truncate` 在 `.endpoint-grid` 里**没有** `min-width: 0`（flex 子项默认
  `min-width: auto`，不收缩），名字撑满后不肯让位；
- `.tag-inline` 是 `flex: 0 0 auto`，也永不收缩，定宽。

两个子项都不收缩，列一窄（可编辑态的 42px 勾选列又抢走一截宽），定宽 chip 就被挤出
`.cell-name`；`<td>` 默认 `overflow: visible`，于是标签视觉上溢到 `.col-path` 列上，盖住路径。

P10-8 那几轮修的是「列预算超卡片宽 / 卡片高度被压扁」，用的是 `.table-scroll` 上的容器
查询（`@container grid`）。本处沿用同一套容器锚点，量表格容器自身宽、不量视口。

## 修法（纯 CSS，`apitest-web/src/design-system.css`）

> **第一版走偏（已废）**：把裁剪压在 `@container grid (max-width: 1100px)` 里。但 owner 两列
> （296px）在 >1100px 容器就已经把名称列挤到 ~120px，1470 宽视口（容器 ~1212px）根本不触发
> 该断点 ⇒ 用户复测「还是一样」。**结论：这处溢出与容器/视口宽无关，不能设断点。**

1. `.cell-name` 加 `position: relative`（作 hover 展开层的定位锚）。
2. `.endpoint-grid .cell-name .truncate { flex: 1 1 auto; min-width: 0; }`——名字先截断让位。
3. 标签常态收缩＋格内裁剪（无断点）：
   - `.endpoint-grid .tag-inline { flex: 0 1 auto; min-width: 0; overflow: hidden; }`——标签允许
     收缩、在格内裁剪，永不溢出到路径列（原 `flex: 0 0 auto` 定宽才会被挤出格）；
   - `.endpoint-grid tr:hover .tag-inline { flex: 0 0 auto; overflow: visible; background: var(--hover); }`
     且 `tr:hover .cell-name { z-index: 1 }`——hover 整行时标签取回自然宽、就地展开显示全部，
     不透明底（行 hover 同色 `--hover`）盖住下方路径；`max-width` 过渡用 `--t`（120ms）。

不改数据、分页、DOM 结构。同处 `.tag-inline` 也用在流程/用例套件等列表（`FlowList`/`SuiteList`
等），本次只对 `.endpoint-grid` 作用域内收敛，其余页保持原样。

## 追加：接口表 owner 两列改「横滑」而非「收列」（用户取舍）

**背景**：P10-8 第三轮为防名称列被挤没，在 `@container grid (max-width: 1100px)` 下把
`创建人/更新人`（`.col-owner`，2×148px）整列 `display: none`。用户在 1370×609（容器 ~1095px）
看到这两列被隐藏，明确要求：1470×724 这类分辨率要**保留**两列、装不下就让列表**横向滚动**。

**改动（纯 CSS，仅作用于 `.endpoint-grid`，其余列表仍按通用收列档）**：

1. `.endpoint-grid .col-owner { display: table-cell; }`——高特异度（0,0,2,0）压过容器查询里的
   `.col-owner { display: none }`（0,0,1,0），接口表 owner 两列在任何宽度都不再被收掉。
2. `.table-scroll > .grid.endpoint-grid { min-width: 1160px; }`——双类压过后面的
   `.table-scroll > .grid { min-width: 720px }`；容器窄于 1160px 时表体不再压缩，横向滚动落在
   `.table-scroll` 自己身上（sticky 操作列常驻右缘，页面本身仍不横滚）。
3. `.endpoint-grid .col-path` 宽度 `28% → 22%`：min-width 下把余量还给名称列，名称在
   editable（多 42px 勾选列）态仍有 ~150px 可读。

**效果**：1470 视口容器 ~1195px 放得下、不出横向条、两列在；1370 视口容器 ~1095px 起触发横滑，
两列照常在。其余用到 `.col-owner` 的列表页（流程/场景/环境/数据源/用例库/Mock/执行记录等）
不受影响，仍在 ≤1100px 容器收起 owner 列。
