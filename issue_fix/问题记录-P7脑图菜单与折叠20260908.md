## ① 右键菜单唤出后，点画布空白处关不掉

- **现象**：脑图节点右键唤出菜单后，点击菜单外任何地方（画布、节点）菜单都不
  消失，只能再点一次菜单项；用户预期「点击框外即取消」。
- **根因**：关闭监听挂在 `document` 的 `mousedown` **冒泡阶段**——而画布的
  mousedown 被 d3-zoom 的 `nopropagation`（`zoom.js` `mousedowned`，平移手势
  在目标层就拦截冒泡）截住，document 层根本收不到「点画布」这一下；画布恰好是
  菜单外最大的点击区域，于是「点外面」在主路径上全部失效。点页面其它区域（筛选
  栏、树面板）本可以关掉，但视觉焦点都在画布上。
- **修法**：监听改挂**捕获阶段**（`addEventListener(type, fn, true)`）——捕获沿
  document → target 先于目标处理器派发，`stopPropagation` 拦不住；顺带补 Esc
  关闭（编辑态的 Esc 由 MindEditInput 自己 stopPropagation，不冲突）。
- **状态**：已修复（2026-09-08，待复测）。

## ② 多模块下折叠子目录后画布内容不展示（附控制台报错取证）

- **现象**：全部用例视图下有多个模块时，折叠某个子模块目录，画布内容不再展示
  （空白/只剩控件）。控制台伴随报错：

  ```
  VM62484:2 Uncaught TypeError: Cannot read properties of undefined (reading 'startTime')
      at et.reportAllChanges (<anonymous>:2:19429)
      at n.timeout (<anonymous>:2:5652) …
  ```

- **根因（报错本身是 Chrome DevTools 的已知 bug，与本项目无关）**：`VM` 前缀 +
  `<anonymous>` 匿名脚本是 DevTools 注入代码的标志；`reportAllChanges` 是
  DevTools 内嵌 web-vitals 库的函数，软导航后 performance entry 被清空、异步
  处理时读 `undefined.startTime` 崩掉——与
  [GoogleChrome/web-vitals#792](https://github.com/GoogleChrome/web-vitals/issues/792)
  / [angular/angular#70464](https://github.com/angular/angular/issues/70464) 完全
  同形（连 `:2:19429` / `:2:5652` 偏移都一致），只在开着 DevTools 的 Chrome
  出现。本仓库依赖树（`grep -r reportAllChanges node_modules`）无此符号，可排除
  应用侧来源。它是**干扰项**，但时间上与画布空白同帧出现，被一并上报。
- **根因（画布空白本体）——两轮归因**：
  - 第一轮按 ㉓ 白屏同类修了**引用稳定性**（见下修法①）：折叠时 `buildGraph`
    整图重建，全部幸存节点也被换成新引用、打进 adoptUserNodes 慢路径重置。
    该修复方向正确（消除整类重置竞态）但**不是本案的可复现路径**。
  - 第二轮复测（用户操作序列：左树点开【测试】目录 → 脑图内折叠 project X）
    后定位到真凶——**视口悬空**：查库取证，测试目录 152 条用例里 151 条在
    project X 子树下；折叠后剩余节点全聚到坐标原点附近，而视口仍停在原来的
    大片区域（fitView 在 minZoom 0.2 下本就装不下整树，用户必然平移过），
    剩余内容全部落在视野外——画布读作「用例消失了」。`toggleNode` 不标记
    「正在操作的节点」，视口 effect（只平移操作节点）因此从不介入。
- **修法**：① 引用稳定（第一轮，保留作加固）：nodes memo 保留上一代渲染等价
  节点的旧对象（`sameMindNode` 全字段比较，编辑闭包按引用比较防旧闭包残留），
  未变节点走 adoptUserNodes 快路径零重置；② **视口分岔**（第二轮，治本）：
  目录 ⊕/⊖ 是结构性视图变化——折叠/展开后按新图重新框定（`fitView`
  maxZoom 1，防放得过大）；用例 ⊕/⊖ 仍是小增量——保持视口，标记选中、节点
  跑出视口时平移回来（㉙ 纪律不变）。
- **验证**：`buildGraph` 布局数学用 Node 脚本按「多模块 + 各级折叠 + 目录作用域 +
  分页 more」矩阵模拟，无 NaN / 无空图 / root 恒在——排除布局层。浏览器复测按
  AGENTS.md 留给用户。
- **状态**：已修复（2026-09-08 第二轮，待复测）。

## ③ 列表「模块路径」列挤占前段、长路径撑爆列宽

- **现象**：模块路径列在编号/标题之前，路径随目录层级任意长，把标题列挤窄；
  超长路径整列被撑开不可读。
- **修法**：模块路径挪到**末列**（操作列之前）并钉 `max-width: 220px`
  （`.spec-case-grid td.col-path`）——超长省略（.truncate），完整路径靠单元格
  title 悬停展示（原本就有）。
- **状态**：已修复（2026-09-08）。

## ④ 左树目录名过长把面板撑出横向滚动

- **现象**：`project X测试用例（SC系统）` 这类长名把 264px 树面板撑出横向
  滚动条（.spec-tree 的 overflow-y:auto 使 overflow-x 计算为 auto）。
- **根因**：`.tree-label` 的名字 span 是 flex 子项，默认 `min-width: auto`
  不肯收缩，`.truncate` 的省略号永远不触发。
- **修法**：`.tree-label .truncate { flex: 1 1 auto; min-width: 0 }`——名字
  可缩出省略号；悬停行上的 `title={module.path}` 展示完整路径（含全名）。
- **状态**：已修复（2026-09-08）。

## ⑤ 删除目录两层确认太重

- **现象**：树面板删除目录先弹「删除？」，目录含用例时 409 再弹第二层「含 N 条
  不可恢复？」——两层弹窗打断操作。
- **根因**：第一轮实现照搬后端 409/force 两段协议，把「先看计数」做成了第二次
  弹窗；但子树计数（目录数 + 用例数）树面板**本地就有**（caseCount 直属求和、
  modules 前缀过滤），不必先撞一次 409 才知道。
- **修法**：**单层确认**——计数直接写进确认文案（「该目录树共 N 个目录、M 条
  用例，删除后无法恢复」），看过数量后一次 `force=true` 删除。计数是树快照、
  与库有一拍延迟，force 删的是整棵子树、不依赖计数精确；确认仍保留（树面板
  没有脑图的 ⌘Z 撤销栈）。
- **状态**：已修复（2026-09-08）。

## ⑥ 单目录数据量大时整页截断，剩余用例不可达

- **现象**：脑图初始只载当前范围前 100 条，超出部分只有根级一行「还有 N 条
  未展示，缩小范围或切回列表核对」——目录内长尾用例在脑图里**永远看不到**；
  case 扩张后（单目录数百条）问题放大。
- **修法**：**目录级局部加载**——初始页仍是范围一页 100 条，但每个「直属已载
  < 树计数」的目录（含范围根本身）在子末尾挂一枚「加载更多（还有 N 条）」
  节点；点击按 `moduleId` 精确取该目录下一批（50/批）追加，按 id 全局去重
  （keep-first，初始页优先保引用稳定）。页码从已载数换算（floor(loaded/50)+1），
  重叠行由去重吸收、绝不跳号；取回空页（计数快照过时）时标记该目录取尽撤下
  节点。范围/筛选变化即作废追加页；revision 重取只刷首页不动追加页（不闪）。
  有关键字/优先级/状态筛选时不启用（树计数是全状态口径，剩余数会虚高），退回
  根级 more 兜底（total 是过滤后的准确值）。viewer 也可加载（读操作）。
- **状态**：已实现（2026-09-08，待复测）。
