# 问题记录 — P7 文本用例库脑图（2026-09-08 第三轮验收反馈，八项 + 一项伴生）

> 范围：脑图七项 + 左侧模块树一项（⑧⑨ 为同日稍后追加的反馈）。①② 同根因
> （本地合入只写首页行集，漏了目录级「加载更多」的追加批），合并归因；③ 是
> 上一轮「折叠后消失」修法（fitView 重框定）的体验反噬，本轮换成保持缩放的
> 平移兜底；⑦ 是 ①② 修复时暴露的撤销链路伴生问题。

## ① Tab 新增用例后，编辑用例不生效（展示的还是旧标题「新用例」）

- **现象**：脑图里 Tab 建用例、就地改名提交后，节点短暂换新又弹回占位标题；
  对「加载更多」装进来的用例做就地编辑同样不生效。
- **根因**：画布行集是**两处拼的**——`data.items`（范围首页 100 条）+
  `moduleExtra`（目录级加载更多的追加批），而 `applyLocalCase` 只合入
  `data.items`。两个破绽叠在一起：
  1. 住在追加批里的行：编辑先短暂生效（被追加进 data.items），随后 revision
     重取**整页替换** data.items（首页装不下它），`moduleExtra` 里的**旧快照行**
     重新接管节点——展示弹回旧值；
  2. 新建用例：服务端按 `ORDER BY m.path, item_key` 排序，新用例编号最大、
     排在范围**最末**——超过 100 条的范围里它根本不在首页，重取后节点直接
     消失（就地编辑输入框也被「目标不在图里」的清理 effect 顺手关掉）。
  另外 total 只查 data.items 就 +1，追加息行的编辑会虚增计数。
- **修法**：`applyLocalCase` 两处都写——页内行照旧合入 items；行在追加批里
  时合入 `moduleExtra[moduleId]`（按 id 原位替换）；未知行（新建）两处都落，
  追加批是它在 revision 重取后的唯一宿主。total 只对「两处都没有」的行 +1。
  顺带把撤销/重做闭包也接上本地合入（见 ⑦）。
- **状态**：已修复（2026-09-08，待复测）。

## ② 脑图按 Delete 删除用例后，展示的还是之前的内容

- **现象**：Delete 删用例，画布上节点不消失。
- **根因**：与 ① 同一家族——`removeLocalCase` 只滤 `data.items`，行住在
  `moduleExtra` 里就永远删不掉；revision 重取又只换首页，追加息原地不动。
- **修法**：`removeLocalCase` 两处一起滤。同族补两刀：删**目录**（deleteModuleNow）
  此前完全不做本地清场——被删子树住在追加页里的行会在目录节点撤下后以
  「孤儿」身份挂回 root（buildGraph 的挂不上目录兜底），新增
  `removeLocalModuleRows`（按子树 moduleId 集滤两处行集，total 按删除前快照
  全量计数先减、重取对齐）。
- **状态**：已修复（2026-09-08，待复测）。

## ⑦（①② 的伴生修复）⌘Z 撤销 / ⇧⌘Z 重做在大范围下「看起来没反应」

- **现象**：范围超过 100 条时删掉一条再 ⌘Z，服务端已恢复、画布上什么都不
  出现（恢复的行新编号排在末尾，不在重取首页里）。
- **根因**：撤销闭包此前刻意不做本地合入——闭包捕获入栈时的 `modulePath`
  prop，晚执行的合入会把旧目录的行塞进切换后的新视图（㉒ 同款危险）。
- **修法**：合入守卫（`applyLocalCase` / `removeLocalCase` /
  `removeLocalModuleRows` 的 `pathAtStart !== modulePath`）改读 `modulePathRef`
  （每次渲染同步的**调用时刻真值**）——切走不合入、切回来又能合入，正是 ㉒
  守卫的本意，旧闭包危险被 ref 化解。`pushCasePatch`、新建/删用例、删目录的
  undo/redo 闭包全部接上合入（删目录的 undo 逐条 `applyLocalCase` 让重建行
  即时上图，redo 按重建后的新子树 id 集清场）。
- **状态**：已修复（2026-09-08，待复测）。

## ③ 折叠/展开目录每次都整图缩放跳变

- **现象**：点目录 ⊕/⊖，画布每次都重新框定（fitView），展开大目录时整树被
  缩出去一大截，定位丢失，「跳转体验很差」。
- **根因**：上一轮修「折叠后用例消失」时给目录切换加了 fitView 重框定——
  消失的问题是没了，但每次折叠/展开都带来缩放跳变。
- **修法**：撤掉 fitView 分岔（fitToken 机制整段删除），回到 ㉙ 纪律：**缩放
  永不变**。折叠/展开后把该目录标记为选中，复用既有的视口 effect——节点跑
  出视野时按当前缩放平移回来。「折叠后消失」（视口悬空在已折叠的大区域）
  由同一条兜底：操作的节点被平移回视野，剩余内容聚在它周围。
- **状态**：已修复（2026-09-08，待复测）。

## ④ 双击左侧模块树目录，视图跳到「全部用例」

- **现象**：双击树里的目录，右表/脑图跳回「全部用例」。
- **根因**：`selectModule` 是**开关语义**（点目录选中、再点一次取消）——双击
  的第二次点击把第一次刚选中的目录又取消了。
- **修法**：双保险。① `selectModule` 记录最近一次点击（模块 id + 时刻），
  同一目录 400ms 内的快速第二击不回退（双击不是「取消」意图）；② tree-label
  补 `onDoubleClick` 强制选中兜底——覆盖浏览器双击判定窗口（~500ms）比
  400ms 宽的边角（慢速双击先被开关取消、再被 dblclick 压回选中）。慢速的第
  二击仍是原取消语义。
- **状态**：已修复（2026-09-08，待复测）。

## ⑤ 悬停提示出来太慢

- **现象**：脑图节点、左树目录、列表模块路径列的悬停提示要等约 1 秒。
- **根因**：与 2026-08-30「悬停提示延迟过长」同款——原生 `title` 属性的延迟
  由浏览器决定且不可调；当时只换了仓库用例树/抽屉/run 明细，本页三处仍是
  原生 title。
- **修法**：同一枚 `Tip` 原语（antd Tooltip，`mouseEnterDelay 0.1`）替换三处：
  脑图节点（编辑态不出——草稿就在眼前）、左树目录（全路径）、列表模块路径列
  （截断从 td 移进内层 span 并钉 block，铺满 220px 上限的单元格，空白处悬停
  也出提示）。
- **状态**：已修复（2026-09-08，待复测）。

## ⑥ 脑图右键菜单太长，优先级/状态应收进子菜单

- **现象**：用例节点右键菜单 12 行（加步骤/加用例/标签/优先级×4/状态×3/
  删除），一屏装不下。
- **修法**：`MenuItem` 支持 `children`——优先级、状态各自收进**悬停展开的
  子菜单**（与父菜单同一套 token；`is-flip` 在菜单贴右缘时整组向左翻），当前
  值打勾 + accent 字色标出。用例菜单收敛为 6 行。纯 CSS 悬停展开配一座
  「悬停桥」（`.mindmap-subwrap:hover::before`，仅 hover 时存在、画在真实子
  元素之下）：指针从触发行斜向滑进子菜单时 `:hover` 不断、子菜单不闪关，
  也不挡子菜单条目的点击与画布。
- **状态**：已实现（2026-09-08，待复测）。

## ⑧ 每次添加/删除后，画布整体闪一下（步骤内容闪）

- **现象**：脑图里每次添加或删除（Tab 建用例/步骤、Delete 删行）落库后，
  展开的步骤内容闪一帧，读作「页面刷新了一下」。
- **根因**：编辑链路是「乐观合入 + onSaved 推 revision 重取」——重取的
  `setData(result)` **整页换新对象**，所有行的 `caseItem` 引用全断，
  `sameMindNode`（渲染等价保留旧节点对象）对全图失效：每个节点都被打进
  React Flow 受控节点按引用判等的**慢路径**（measured/handleBounds 重置、
  ResizeObserver 重测，㉓ 的病理），整树闪一帧。SpecCases 的 `loadModules`
  同样整页换 modules，目录节点的 `module` 引用跟着全断。
- **修法**：重取落库改为**保引用合并**——脑图取数按 `id + updatedAt` 判等
  （任何落库都推 updated_at，等价即内容未变），没变的行用旧对象，节点判等
  走快路径零重置；modules 按 name/parentId/path/position/caseCount 逐项判等
  同款处理。真正变了的行（自己刚编辑的、远端改动的）才换新对象——必要的
  重渲染不受影响。
- **状态**：已修复（2026-09-08，待复测）。

## ⑨ 脑图单格长宽装不下内容（「展示不完全」）

- **现象**：节点内容展示不完全——导入的长步骤/前置/用例标题在 224px 单行
  里截断，与 XMind 本体（话题框按内容折行）观感不符，读作节点 CSS 长宽
  有问题。
- **根因**：设计而非盒模型 bug——`* { box-sizing: border-box }` 全局生效、
  高度与 NODE_H 对齐都正常；问题是内容节点（用例/前置/步骤/预期）钉了
  **单行**：`.truncate` 的 nowrap + `max-width: 224px`，一行 ~17 个汉字，
  XMind 导入的步骤是长句（导入映射还按换行拼接前置/预期），一行装不下。
- **修法**：内容节点改**两行折行**——`.mindmap-label` 在 case/pre/step/exp
  下覆盖 `.truncate` 为 `line-clamp: 2`（CJK 自然断行 + anywhere 兜底长串），
  节点高 32/28 → 44（= 2 行行高 + 边框呼吸），`NODE_H` 常量严格同步（布局
  按它算，CSS 不钉会漂）。目录/root 保持单行（结构行、名字短、带计数）；
  超两行仍省略，悬停 Tip 看全。同轮顺带：脑图提示条尾部标注「未接入 OT
  算法，不支持多人协同」（边界 17 的前端落点，非缺陷，记计划）。
- **状态**：已修复（2026-09-08，待复测）。
