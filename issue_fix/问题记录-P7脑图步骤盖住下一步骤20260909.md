## 脑图内 case 的某个步骤内容过大时，盖住下一个步骤的内容

- **现象**：展开一条用例，某个步骤的文字很长（多条折行）时，该步骤节点
  盖住紧随其后的下一个步骤节点的内容。
- **根因**：`place()` 给父节点让位**只看子代跨度**，父节点自身高度不参
  与占位。带预期的步骤是内部节点（子代 = 一条预期），它的纵向槽 = 预期
  的跨度；步骤自身被居中在这条预期上。长步骤（如 4 行 ≈107px）配一条短
  预期（1 行 ≈53px）时，步骤上下各溢出 (107−53)/2 = 27px，下方溢出吃掉
  GAP_Y(12px) 后仍压进下一个步骤的槽 15px——内容越大盖得越多（8 行步骤
  盖 51px）。同理可复发于：长标题用例只剩「＋ 前置 / ＋ 步骤」占位槽
  （子代跨度仅 60px）、长标题用例只带一条短前置。无预期的步骤是叶子，
  槽 = 自身全高，不受影响——这就是「同样的长度，带预期的步骤才盖人」。
- **修法**：先量后排。新增 `measure()`（memo Map）算子树占位高
  `max(自身高, 子代跨度)`；`place()` 中自身高于子代跨度时子代整体下移
  `(h−span)/2` 让位（父节点钉在槽顶、子代居中于它），返回的 `bottom`
  扩张为 `max(子代末, 自身底)`——下一个兄弟从真正的底缘排起。自身 ≤
  子代跨度（绝大多数场景）保持原行为不变（居中于首末子代中心、bottom =
  子代末），`max` 只兜极不对称下 1px 级的下探。估算行数与 CSS 几何本身
  无漂移（第五轮①已对齐），无需动 `estimateLines`/`nodeHeight`。
