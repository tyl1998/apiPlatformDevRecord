# 问题记录 — 助手未配置时「列表报错 + 建会话白屏」

- 阶段：P9 用户级化之后的用户实测（2026-09-17）。
- 涉及：`apitest-server/src/routes/assistant.ts` 的 `loadResolvedDefaultAgent`
  守卫；`apitest-web/src/components/AssistantDock.tsx` 的会话列表取数效应与
  `createConversation`。

## 现象

助手 provider 与个人 agent 都没配置时（空库，或这台机器上这个人没配 agent）：

1. 点开站内助手（个人助手入口）后拉会话列表，弹一条「会话列表加载失败」；
2. 点「新会话」，抽屉内容当场白屏，整个聊天面渲染不出来。

## 根因

守卫少回一个 fail，路由以 **HTTP 200 + 空体** 收场。

`loadResolvedDefaultAgent` 只处理了「凭据解密失败」这条腿（catch 里 `fail`），
`loadEnabledDefaultUserAgent` 正常返回 `undefined`（这个人没有默认 agent）时
只是 `return undefined`，**没有回任何响应**。调用方 `if (!await …) return;`
提前返回后，Fastify 把这个「没发过响应的 handler 返回」写成 200 空体
（curl 实测：`HTTP/1.1 200 OK`、`content-length: 0`）。

前端按正常契约解 `response.data.data`，于是：

- `GET /assistant/conversations` → `rows` 是 `undefined`，`rows.some(...)`
  抛 TypeError，被 `.catch` 接住 → 弹「会话列表加载失败」（本该是「未配置」
  引导，不是错误）；
- `POST /assistant/conversations` → `created` 是 `undefined`，被塞进
  `conversations` 后渲染遍历 `conversation.id` → 渲染期抛错 → 白屏。

即两条症状同源：**503/2005 的「未配置」信号在这条腿上漏发了**，前端把
「没有数据」误当成「有数据」。

## 修法

后端（根因）：`loadResolvedDefaultAgent` 补上「没有默认 agent」这条腿的
`fail(reply, 503, 2005, NO_DEFAULT_AGENT)`，守卫回到「拒绝即已回完」的契约
（`server-contract` 规则 2）。会话列表 / 建会话 / 发消息 / 停止 / 历史五条
路由都在这个守卫后面，一处修全体归位。

前端（防御）：`AssistantDock` 不再假设成功响应一定有内容——
`s.createConversation` 拿不到 `created.id` 按失败收口，绝不把空行进状态；
列表取数对非数组载荷按加载失败处理，且**闸门语义（503/2005 未配置、404 已关）
不再弹错误 toast**——那是引导，用户的下一个动作在设置卡里，不在重试里。

配套：新增启动种子（`seedAssistantProvider`，名字 `nuwax-agent`，按名字幂等、
baseUrl 取 `NUWAX_BASE_URL`），任何库缺这一行就补上、空库时它同时是默认，不必等
管理员手配；详见开发计划 P9 章节 13.4.5。
