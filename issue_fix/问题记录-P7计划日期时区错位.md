# 计划编辑后截止时间消失（DATE 列时区错位）

- 日期：2026-09-09（计划详情第四轮反馈第 2 项）
- 模块：apitest-server `src/models/types.ts`（mapTestPlan）

## 现象

计划设置了截止时间后，点「编辑」打开弹窗：截止日期输入框是空的；列表页「截止」
列此前能显示（`toLocaleDateString` 恰好容错），但 `<input type="date">` 不认
非 `YYYY-MM-DD` 的 value，直接清空——用户读作「编辑后看不到」。

## 根因

pg 驱动把 Postgres `DATE` 列解析成 **Date 对象**（不是字符串），挂的是**本地时区
午夜**：库里 `2026-09-23` 读出来是 `2026-09-23T00:00+08:00`（ISO 视角
`2026-09-22T16:00Z`）。`mapTestPlan` 用 `String(row.due_on)` 映射，产出
`"Wed Sep 23 2026 00:00:00 GMT+0800 ..."`：

- 不是 API 该有的 `YYYY-MM-DD` 形状（TS 类型的谎言——`dueOn?: string` 说它是）；
- 塞进 date input 是非法 value → 回填清空。

注：写路径没坏（前端发 `YYYY-MM-DD`、`$::date` cast 入库，库里值正确）——
纯粹是读路径的映射形状错。

## 修法

`mapDateOnly(value)`：Date 对象取**本地分量**三件套拼回 `YYYY-MM-DD`
（「本地午夜」里的本地年月日就是入库的日期字符串；取 UTC 分量会差一天——
东八区 09-23 本地午夜 = 09-22T16:00Z，实测两个方向都跑过才落笔）。
`startedOn` / `dueOn` 走它。对 dev 库真实行验证：修正输出 = `due_on::text`。

## 状态

已修（`mapTestPlan` 一处 + 新增 `mapDateOnly`）。api 是 `tsx watch` 自动热重载；
待用户重新打开编辑弹窗复验（截止日期应回填）。
