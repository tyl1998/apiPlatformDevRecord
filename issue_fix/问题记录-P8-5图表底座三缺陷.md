# P8-5 图表底座三缺陷：hover 错位 / 断线不可读 / ingest 耗时样本污染

> 2026-09-10 用户实测趋势页报告三个问题。前两个是 P8-5 图表底座（`components/charts/`）
> 自伤缺陷，第三个是 P3 起就存在的 ingest 数据缺陷、被新图放大后暴露。
> 开发内容见 `DEVELOPMENT_PLAN_P6-P10.md` 十二章；缺陷记本文件。

## ① hover 选中点不跟鼠标（底座缺陷）

**现象**：趋势页折线/柱图上悬停，指针在位置 A，实际吸附的是 B 点，且越靠右偏得越多。

**根因**：底座 SVG 写了 `width="100%"` 但漏了 `preserveAspectRatio="none"`。SVG 默认
preserveAspectRatio 是 `xMidYMid meet`——容器比 viewBox（720px）宽时内容按 1:1
居中留白、**不拉伸**，绘图区只占容器中间一段；而 hover 反查用「offsetX / 容器宽」
算比值。容器 1000px 时绘图区从 ~440px 才开始，指针横坐标被系统性高估，吸附点
持续右偏——正是「指 A 选 B」。

**修法**：`LineChart` / `StackedBars` / `Sparkline` / `Donut` 四个组件的 SVG 全部
显式补 `preserveAspectRatio="none"`（Donut 是正方形不受影响，一并声明防未来改尺寸
时踩同一个坑）。注释写明理由。

**状态**：已修。宽容器下指针与十字线/高亮柱对齐。

## ② 折线没有连续性（底座语义分叉）

**现象**：项目内折线画出来的线碎成几段，稀疏窗口（24h 只跑过几个桶）下几乎看不到线。

**根因**：底座沿用了 P3-9 的「null 桶断线」规则且不可配置。该规则对通过率是对的
（「没执行」跨过去会读成「维持不变」），但对耗时分位数这类「每桶独立结论」的序列，
断线表达的「这个桶没样本」信息价值低于可读性代价——24 个桶只有 3 个有样本时，
断线只剩 3 段碎线，孤立单点甚至连 path 都画不出来（单点段被丢弃）。

**修法**：`core.ts` 的 `pathSegments` 加 `{ bridgeGaps }` 选项——true 时跨 null 桶
连线；两种模式都补「孤立单点成段」（`M x,y L x,y`，round linecap 渲染成点）。
消费方按序列语义选择：`Trends.tsx` 耗时分位图开 `bridgeGaps`（「没样本」仍由读数条
的「—」表达），通过率图保持断线；`Sparkline` 固定桥接（22px 高的形状图里断线只剩
几个孤立点，语义表达不出来）。

**状态**：已修。耗时分位图在稀疏窗口连成可读的一条线。
**复验追记（同日）**：首修给孤立单点补的「零长 `L` 段 + round linecap」不够——
linecap 只渲染**线宽大小**的点（1.5px，肉眼不可见），`stroke-dasharray`（p99
虚线）下零长 path 更是什么都不画，「只有一个点根本看不见」。改为显式
`<circle>`：`core.ts` 新增 `isolatedIndices`（断线模式：值非 null 且左右邻居皆
null 的下标）与 `singleValueIndex`（桥接模式：全序列恰好一个非 null 值时返回
它——桥接线上其余点都有线经过，不画点避免点标记噪声），`LineChart` 按模式取
其一渲染 r=2.5 的 circle（与 hover active 点同径，悬停时两层重合不闪）；
`Sparkline` 不需要——它的末点 circle 天然覆盖全序列单点。零长 L 技巧从
`pathSegments` 移除，注释写明「单点段别指望 path 可见」。

## ③ 耗时分位数出现 278824s / 139412s（ingest 数据缺陷，P3 起存在）

**现象**：趋势页耗时分位图的 y 轴刻度出现 278824s（≈3.2 天）、139412s、0ms。
278824s 是 max、139412s 是 max/2——即有桶的 p99 ≈ 3.2 天。

**根因**：`lib/ingest.ts` 写 `execution_index` 行时 `finished_at` 兜底
`new Date().toISOString()`（上报接收时刻），且重投的 ON CONFLICT UPDATE 分支
**无条件覆盖** finished_at。dev 库实测（行 479ecada）：9/4 的 CI 上报带了真
started_at、没带 finishedAt → 兜底写入 9/4；9/8 同 commit 重投一份同样没带
finishedAt 的 payload → 覆盖成 9/8 的 now()。`finished - started` = 3.94 天，
把整个窗口的 p99 拉爆。P3 起就在，趋势页升级为手写 SVG 分位图（P3-9）后才在
y 轴刻度上显形。

**修法**（两层，代码 + 数据）：

- 代码：`ingest.ts` 索引行写入改两个纪律——① 首投兜底 `now()` 但**仅当
  `started_at` 没有真值**（有真 started_at 而 finished_at 兜接收时刻，
  `finished - started` 就是假耗时）；② 重投只在 payload 带真值时覆盖
  （`COALESCE(EXCLUDED.finished_at, 原值)`——SDK 分批上报第一投没带、第二投
  补真值的正常路径不受影响）。`ingest_runs` 侧 upsert 本就是 COALESCE 保留，
  不动。
- 数据：把库内唯一被污染的行（execution_index 479ecada）的 `finished_at`
  置 NULL——无法还原真完成时刻时 NULL 是诚实值，趋势 SQL 的
  `FILTER (WHERE finished_at IS NOT NULL …)` 会把它排除出耗时样本。修后
  ingest/success 的 p99 从 329819s 回到 401.8s（CI 侧真实值）。

**状态**：已修。y 轴刻度回到秒/分钟量级。
