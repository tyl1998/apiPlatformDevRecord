# P3 验收缺陷（第五轮）

用户手动验收时反馈的问题：两个代码缺陷/功能补齐（套件页白屏、流程列表分页），
一个经取证为非缺陷（环境默认头 + 变量覆盖，与第四轮第 4 项同类）。

## 1. 进入套件页白屏（Rules of Hooks 违规）

- **现象**：进入套件页整页白屏，控制台报
  `Rendered more hooks than during the previous render`，指向
  `SuiteWorkspace.tsx` 的一个 `useEffect`。
- **根因**：第四轮给套件页加 Cmd+S 时，那个 `useEffect` 被声明在了
  `if (!draft) return …`（草稿未加载的早退）**之后**。首帧 draft 未加载、组件早退，
  后面的 Hook 一次都没跑；draft 到位后早退不再发生，组件突然多出一个 Hook——React
  按「Hook 数量变了」直接抛错。是本轮改动自己引入的回归。
- **修法**：把 Cmd+S 的 `useEffect` 移到早退之前（与其余 Hook 排在一起），并加注释
  说明「条件返回之后再声明 Hook 会崩」的原因，防止下一个人再犯。`save` 是函数声明、
  有提升，在声明点之前引用是安全的。
- **状态**：已修复。

## 2. 流程列表没有分页

- **现象/诉求**：接口/数据源/Mock/套件列表都有分页，流程列表没有。
- **修法**：
  - 后端 `GET /flows` 加 **opt-in** 分页（与 endpoints / data-sources / mocks 同一
    约定）：传 `pageSize` 才分页（`page/pageSize/total`，上限 100），不传仍回全量
    ——套件成员选择器的流程 tab、mock 来源等仍依赖全量契约；lastRun 只对当前页的
    流程查询。
  - 前端新增 `api.flowsPaged`，流程列表页换用（20/50/100、真实 total、筛选变化回
    第一页、删空本页自动退页）——与接口列表同一模式。
- **状态**：已实现。

## 3. 「环境默认头 x=2，触发 x=xxx 没生效」——非缺陷（配置方法）

- **现象**：用户在 `debug` 环境默认头里写了 `x = 2`，运行套件带覆盖 `x = xxx`，
  快照里头仍是 `x: 2`。
- **取证**（只读 SQL）：`environments.default_headers = {"x": "2"}`——值是**纯文本
  "2"**，不是 `{{x}}` 模板；三次触发的覆盖（`rrr`/`www`/`eqweqw`）都已冻结入库；
  流程内 `{{index}}`（快照里的 `ss=0..3`）正常解析，替换机制本身工作。默认头的值
  只有写成 `{{x}}` 才会进变量解析链，纯文本是固定值，任何覆盖都改不动它。
- **结论**：与第四轮第 4 项同类——覆盖是**替换值**，不是「按名字盖掉默认头」。
- **修法**（文案）：`environments.defaultHeadersHint` 补一句显式对照——「要被触发
  覆盖切换的头，值里必须写 {{变量名}}（默认值放变量表）；纯文本是固定值」。
- **给用户的正确配置**（三步）：① 环境变量表加 `x = 2`（默认值）；② 默认头写
  `x: {{x}}`；③ 触发时覆盖 `x = xxx`。不触发 → 头是 `x: 2`；带覆盖 → 头变
  `x: xxx`。
- **状态**：机制按设计工作；提示文案已补强。
