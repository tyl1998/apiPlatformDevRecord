# 脚本断言编辑器行布局重构 — 问题记录

日期：2026-08-12

## 需求

将接口编辑 → 用例 → 校验 → 自定义脚本的 UI 控件合并到同一行，顺序为：

```
[自定义脚本Select] [私有脚本Select] [存为公共/脱离] [试运行] [展开按钮] [结果] [✕删除]
```

附加要求：
- 按钮不靠右对齐
- 收起状态下仍显示试运行结果

---

## 涉及文件

| 文件 | 改动内容 |
|---|---|
| `apitest-web/src/components/ScriptAssertionEditor.tsx` | 移除内置 head 行，新增 `collapsed`/`onToggleCollapse`/`onReadyRef` props，试运行结果移出收起守卫 |
| `apitest-web/src/components/AssertionEditor.tsx` | script 类型断言行内联 Select + 按钮 + 展开，通过 `onReadyRef` 回调获取子组件状态 |
| `apitest-web/src/design-system.css` | `.assertion-row` 去掉 `justify-content: space-between`，`.script-editor-actions` 去掉 `margin-left: auto` |

## 问题 1：按钮间距过大

**现象**：`[私有脚本Select] [存为公共/脱离] [试运行]` 三个控件之间间隔很远。

**原因**：`.assertion-block > .assertion-row` 使用了 `justify-content: space-between`，将所有 flex 子项沿行两端均匀撑开。

**修复**：将 `justify-content: space-between` 改为默认值（`flex-start`），并加上 `flex-wrap: wrap` 防止窄屏溢出。

```css
/* 修复前 */
.assertion-block > .assertion-row {
  display: flex;
  align-items: center;
  gap: var(--s2);
  justify-content: space-between;
}

/* 修复后 */
.assertion-block > .assertion-row {
  display: flex;
  align-items: center;
  gap: var(--s2);
  flex-wrap: wrap;
}
```

## 问题 2：删除按钮位置错误（闪烁 / 跑到前面）

**现象**：✕ 删除按钮出现在 `[自定义脚本Select]` 后面，而不是行尾。

**根因**：`ScriptAssertionEditor` 的控件状态（options、isFollowing、content 等）由子组件内部管理，父组件 `AssertionEditor` 渲染行时无法直接获取。采用 `onReadyRef` 回调 + `useLayoutEffect` 方案让子组件在挂载后把状态回传给父组件，但存在以下时序问题：

1. **首次渲染**时 `scriptControlsMap.current[index]` 为空 → 脚本控件不渲染 → 行内只剩 `[类型Select] [✕]`
2. 子组件 `useLayoutEffect` 触发 → 更新 map → 父组件 re-render → 控件出现
3. 虽然 `useLayoutEffect` 在浏览器绘制前执行，但中间态的 DOM 结构不同，可能导致布局闪烁

**尝试过的方案**：

| 方案 | 问题 |
|---|---|
| `makeScriptReadyRef(index)` 每次渲染创建新对象 | 子组件 `useLayoutEffect` 收到新 ref 每次都触发回调，但父组件首次渲染时 map 仍为空 |
| `getScriptReadyRef(index)` 缓存回调（稳定引用） | map 首次仍为空，时序问题未解决 |
| 去掉 `if (!c) return null`，始终渲染控件 | **最终方案** — 用可选链 `c?.pickPublic` 等保证 map 为空时控件仍渲染（只是 disabled 状态），删除按钮位置稳定 |

**最终修复**：去掉 IIFE 中的 `if (!c) return null`，改为始终渲染脚本控件，用可选链访问可能为空的状态：

```tsx
// 修复前
const c = scriptControlsMap.current[index];
if (!c) return null;  // ← 首次渲染时不渲染控件，✕ 跑到前面
return <>...</>;

// 修复后
const c = scriptControlsMap.current[index];
return <>
  <Select value={c?.isFollowing ? c.scriptId : ""} options={c?.options ?? [{ value: "", label: "私有脚本" }]} ... />
  <button onClick={() => c?.publish()} disabled={!c?.content?.trim()}>存为公共脚本</button>
  <button onClick={() => c?.tryRun()} disabled={c?.trying}>试运行</button>
</>;
```

## 问题 3：`margin-left: auto` 导致操作按钮靠右

**现象**：`[存为公共/脱离] [试运行]` 被推到行的最右侧，与左侧控件拉开距离。

**原因**：`.script-editor-actions` 原有 `margin-left: auto`，目的是把操作按钮推到 flex 行右侧。

**修复**：去掉 `margin-left: auto`。

---

## 经验总结

1. **父组件需要渲染子组件内部状态时**，`onReadyRef` + `useLayoutEffect` 方案可行，但必须确保首次渲染时 UI 结构稳定（用 fallback 值代替条件跳过）。
2. **避免在 flex 行中用 `justify-content: space-between`** 搭配少量子项，容易导致间距失控。
3. **子组件状态外提**比回调传参更简单——如果早将 `options`/`isFollowing`/`content` 等提升到父组件，可以避免整个 `onReadyRef` 机制的复杂度。
