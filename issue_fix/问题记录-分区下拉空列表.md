# 问题记录 — 分区下拉空列表（P2-8.7 配置体验补齐期间）

## 现象

环境管理抽屉的「执行分区」换成 AutoComplete 后，用户反馈"没有任何变化"：
点开字段看不到下拉候选，观感与原来的自由文本输入框完全一样。
（复制按钮、`/system/runner-labels` 路由、复制 201 等其余改动均正常生效，
API 日志可证，排除"前端没更新"。）

## 根因

两个叠加：

1. **候选过滤把 `default` 排除了**（从 datalist 时代的建议列表逻辑照搬）。
   datalist 只在输入字符后弹建议，`default` 显示为空、不建议，无副作用；
   换成 AutoComplete 后候选列表就是主交互，而库里 4 个环境**全是 `default`**
   ⇒ 下拉打开永远是空列表，形同没改。
2. **编辑回显沿用"`default` 显示为空"约定**，选中 default 后输入框是空的，
   在下拉语境里读起来像"没选"。

根子是同一条：把 `default` 当成"没有分区"处理，而它其实是
「平台所在网段」这一个真实分区。只有 default 的项目是初装常态，
这种项目打开空下拉是必现路径，实现时没有用它自测。

## 修法

- `Environments.tsx` 候选过滤只剔空串，`default` 进列表；
  候选右侧带状态（`在线 n/m` / `无执行器`），default 与其它标签同权展示。
- 编辑时如实回显 `env.runnerLabel`（default 也显示）；保存仍按
  「空归一成 default」规则，两种输入等价。

## 状态

已修（2026-08-27）。教训记两条：

- 交互范式换了（datalist → AutoComplete），沿用旧范式的显示约定前要重新过一遍。
- 自测要用"初装常态"的数据形态（只有 default 分区），不能只在有多分区的
  假设下看效果。
