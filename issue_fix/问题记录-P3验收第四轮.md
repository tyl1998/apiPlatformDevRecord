# P3 验收缺陷（第四轮）

用户手动验收变量覆盖与套件页时反馈的五个问题。前两项与第三项为交互补齐，
第四项经数据库取证判定为非缺陷（测试方法问题），第五项为新增快捷键。

## 1. 环境管理「默认请求头」未换新组件

- **现象**：变量覆盖已换成环境变量行样式（`VariableRowsEditor`），但环境抽屉里的
  默认请求头编辑器还是旧的 `KeyValueEditor`（表/文本双模式 + 启用勾选）。
- **根因**：第三轮换组件时只换了「变量覆盖」两处（运行弹窗、调度编辑），环境默认头
  作为同机制的第三处被漏掉了。
- **修法**：环境默认头换用 `VariableRowsEditor`；`copyTemplate={false}`——复制按钮
  给头名本身（X-Env-Tag），不是 `{{X-Env-Tag}}`。请求头/参数编辑器仍用
  `KeyValueEditor`（临时停用一行、curl 批量粘贴是那两处的真实动作）。
- **状态**：已修复。

## 2. 套件列表行「运行」不弹变量覆盖

- **现象**：套件列表行的运行按钮直接入队，没有变量覆盖弹窗；同一个 API 的两个入口
  能力不一致。
- **根因**：第三轮只给套件配置页补了运行弹窗，列表行仍是旧的一键直跑。
- **修法**：抽出共享组件 `SuiteRunModal`（持有变量覆盖状态、键名校验、自绘底部
  按钮），配置页与列表行共用；列表弹窗标题带套件名（一次能看到多行，弹窗要说自己
  要跑谁）。变量值在页面会话内保留（antd Modal 不销毁内容）。
- **状态**：已修复。

## 3. 运行弹窗主/次按钮不协调

- **现象**：弹窗底部「运行套件」（antd primary）与「取消」（antd default）内边距
  与排版不一致，视觉不协调。
- **根因**：antd Modal 默认页脚两类按钮的样式差异；应用的其余弹窗/抽屉页脚用的都是
  自绘 `.btn`。
- **修法**：`SuiteRunModal` 改用自绘页脚（`footer` prop）：`.btn` 取消 + `.btn
  btn-primary` 运行，与抽屉页脚同一套按钮。
- **状态**：已修复（随第 2 项）。

## 4. 「变量覆盖没有生效，快照里没有我设置的内容」——非缺陷

- **现象**：用户在运行弹窗填了 `x=123`，运行后成员证据快照里看不到 123。
- **取证**（只读 SQL + 日志，未运行任何验证性执行）：
  - API/worker 均为当前代码（进程启动时间晚于 P3-2/3 落盘时间）；
  - `suite_executions.variable_overrides = {"x": "123"}` ——覆盖**已**随运行冻结入库；
  - 该套件唯一成员是流程「测试调试删除」，其全部节点只引用 `{{index}}` 与
    `{{test}}`，**没有任何 `{{x}}`**；快照里的 `ss=0..3` 等即 `{{index}}` 的解析结果，
    替换机制本身工作正常；
  - 那次运行 failed 的原因是流程内 mysql 节点 `connect ETIMEDOUT`，与变量无关。
- **结论**：变量覆盖是**替换值**：它只在成员里存在 `{{x}}` 占位的地方出现（或经
  环境默认头间接生效，如 `X-Env-Tag: {{x}}`）。填一个无处引用的变量不会在任何快照
  里产生可见变化；它本身会显示在报告/运行抽屉的标识段（`x=123`）。
- **给用户的验证方法**：在成员用例的 URL/头/正文里放一个 `{{x}}`，或把环境默认头
  设成 `X-Env-Tag: {{x}}`，再带 `x=123` 运行，快照里即可看到 123。
- **状态**：无需修复（机制按设计工作）。

## 5. 套件页缺 Cmd+S / Ctrl+S 快捷保存

- **现象/诉求**：接口与流程工作台都有 Cmd+S 保存，套件页没有。
- **修法**：套件页补同款 window 级 keydown（`metaKey || ctrlKey` + `s`，拦截浏览器
  保存对话框；无改动时是空操作，不弹假反馈），与 EndpointWorkspace 的既有实现同
  一模式。
- **状态**：已实现。

## 附：修复验证约定

按项目约定未做自动化/浏览器验证，行为验收由用户手动进行（重启前端后走查：环境
默认头新样式与复制头名、套件列表行运行弹窗、弹窗按钮样式、Cmd+S 保存；变量覆盖
生效性按第 4 项的验证方法自测）。
