## 一、验收反馈问题（用户提出，均已修复）

按反馈批次组织；每条含现象、根因、处理。

### 第一批：工作台侧栏「用例」框（6 项）

### #1 调试记录筛选后条目挤在一起

**现象**：给调试记录加状态筛选后，筛选框与分段控件挤在同一行，300px 侧栏里显得拥挤难看。

**根因**：状态 Select 与「收起」按钮共用 `panel-head` 一行，宽度不足。

**处理**：筛选独占一行 `.side-filter`（status 筛选移至行内），标题行只留分段控件与收起按钮。

**状态**：已修复

---

### #2 断言在保存弹窗里编辑，体验差且与响应上下文割裂

**现象**：保存为用例弹窗里编辑断言，看不到响应 body，无法对着实际返回写规则；弹窗还要承载校验规则，与「调试定义」边界模糊。

**处理**：
- 断言从弹窗搬进工作台，新增**「校验」页签**，与响应面板同屏，未保存时执行用例按屏幕规则试跑。
- 弹窗只保留名称 / 标签 / 环境；页面里通过文案明确区分：左侧页签描述「发什么请求」，校验页签描述「返回必须满足什么」，校验页签**仅在加载用例时出现**，从结构上杜绝与接口定义混淆。

**状态**：已修复

---

### #3 分段切换顺序：用例应在调试记录前面

**现象**：侧栏 `[调试记录 | 用例]`，用户要求用例在前。

**处理**：分段顺序反转为 `[用例 | 运行记录]`，且**用例为默认视图**（`?side=history` 深链仍可直达调试记录）。

**状态**：已修复

---

### #4 用例列表缺少筛选

**现象**：用例多起来后无法检索。

**处理**：用例框顶部加**名称搜索 + 状态（通过/失败/未执行）+ 标签**筛选；标签下拉只列出现有标签。

**状态**：已修复

---

### #5 用例行的「⋯」菜单不可见

**现象**：编辑/删除藏在弹出菜单里，栏目内看不到，300px 侧栏里尤其难找。

**处理**：删掉弹出菜单，改为**行内常驻** 运行 / 编辑 / 删除 三个图标按钮，与接口列表操作方式一致。附带修掉「最近结果」用嵌套 `<button>` 的非法 HTML（改 `role="button"` 的 span，支持键盘）。

**状态**：已修复

---

### #6 执行记录里看不到用例名

**现象**：用例执行后去「执行记录」看，首列只有接口名，分辨不出是哪个用例跑的。

**根因**：执行记录首列只渲染 `endpointName`，`caseName` 虽已入库但未展示。

**处理**：首列改「执行对象」——用例执行显示 `[用例] 用例名 + 所属接口`，调试显示接口名；新增**来源**筛选（全部/接口调试/用例执行）。

**状态**：已修复

### 第二批：入口收敛与保存（3 项）

### #7 调试记录里看不到用例运行

**现象**：侧栏「调试记录」不收录用例执行，用户期望统一看。

**根因**：后端 `endpointExecutions` 对非 `all` 来源默认只返回 `endpoint_debug`——这是我上一轮的设计决策（当时认为「调试记录 = 临时验证，用例回归另属一栏」），与用户期望不符。

**处理**：改**默认返回全部来源**，`source` 只作显式收窄；侧栏改名「运行记录」。

**状态**：已修复（并同步 `DEVELOPMENT_PLAN.md`）

---

### #8 三个用例创建入口太零散；且用例编辑后无法保存（本轮最严重的设计缺陷）

**现象**：
1. 用例列表底部有「新建用例」、页面顶部有「另存为新用例」、请求区有「保存为用例」——三个入口含义重叠。
2. **加载用例后请求改动无处落盘**：顶部只有「另存为新用例」，唯一能保存的是断言，「保存用例」按钮缺失。

**根因**：我为「快照隔离」过度设计了保存入口——把「用例请求不可被页面改写」误解成「编辑后不能保存」，只给断言单独保存，请求快照只允许派生新用例。

**处理**：
- 入口收敛：删用例列表「新建用例」、删请求行图标入口；调试态唯一创建入口 = 顶部「保存为用例」，响应面板快捷入口保留（刚发完就存的顺手动作）。
- 加载用例后顶部出现主按钮**「保存用例」**，一次性写入请求快照 + 校验规则（后端 PATCH 支持整体改写 `request_snapshot` 与 `assertions`）；「另存为新用例」退为次要的派生变体动作。
- 保存为用例后**自动加载该用例**（带 keepResult，保留刚生成的响应），并切到「用例」视图。

**状态**：已修复

**处理**：移到标题下方，与描述同行（`.head-meta`）；底部旧标签栏删除。

**状态**：已修复

### #10 响应结果框里不需要「保存为用例」

**现象**：响应面板的保存按钮与顶部入口重复。

**处理**：删除响应面板内的入口，顶部操作栏是唯一创建入口。

### #11 JSONPath 期望值需要从响应 Body 快速提取

**需求**：断言配置时，希望从实际响应里勾选路径，而不是手写 `$.data.token`；勾选多个则生成多条断言。无响应时先提示发请求。

**处理**：新增 `JsonPathPicker`——响应 body 解析为可勾选树（对象/数组节点可折叠，标量叶节点可勾选）；第一条路径填当前行，其余追加为 `exists` 断言行。路径生成（`step()` 点号/括号转义）与后端 `readPath` 对齐，用 8 个含特殊键/嵌套数组的用例验证全部可解析。

**状态**：已修复

---

### #12 参数 / 请求头需要文本分割模式

**需求**：整段复制 curl / 文档里的参数与请求头，按行解析回表格，也支持表格转文本复制。

**处理**：`KeyValueEditor` 加表格/文本切换。格式 `key: value` 或 `key=value`，**按首个分隔符切分**（值里的 `:` `=` 保留），整行 `#` / `//` 为注释。

**状态**：已修复（文本解析 bug 见 #19）

### 第四批：切换按钮位置与信息密度（3 项）

### #13 表格/文本切换按钮位置反复（两轮）

**现象**：
1. 第一版图标浮在编辑器行上方，孤立无归属，用户明确说「塞在那里不合适」。
2. 改为文字分段控件放标题行右侧，用户仍说没靠右、且要求「按钮不要文本，用回图标」。

**根因（靠右失败）**：`.kv` 容器 `align-items: flex-start`，导致 `.kv-head` 收缩为内容宽度，`justify-content` 无从生效。

**处理**：切换改回图标按钮；`.kv-head` 改为默认 stretch + `.subhead { flex: 1 }` 撑满，按钮 `margin-left` 归位到最右；`ModeSwitch` 抽成共享组件供断言编辑器复用。

**状态**：已修复

### #14 校验页签信息过多

**现象**：外层「用例校验：测试ddd」标题 + 长提示 + 内层「校验规则 N」标题 + 数量徽章，四层信息堆叠。

**处理**：删外层标题与提示、删数量徽章，只保留「校验规则」标题 + 判定规则提示语（「只要有一条不通过，本次执行即判定为失败（即使 HTTP 返回 200）」）。

**状态**：已修复

### 第五批：保存行为（2 项）

### #15 保存不够便捷 → 绑定快捷键

**需求**：每次点保存按钮操作太多。

**处理**：绑定 `⌘S`（Mac）/ `Ctrl+S`（其他），用例态保存用例、调试态保存接口；「未保存」徽章直接标注快捷键（「未保存 · ⌘S 保存」）。effect 声明在 dirty 标志之后（#24），依赖数组含 `draft` / `caseAssertions` 防闭包过期。

**状态**：已实现

---

### #16 点击执行后保存提示的取舍（方案 A）

**现象**：用户发现「改动后点执行也是按最新执行的」，问是不是走了默认保存。

**结论**：是。调试态执行路由 `/endpoints/:id/execute` 由服务端**读库**发起，屏幕改动必须先落库才生效，故 `send()` 会先自动 `save()`——这是 P0 就有的设计，非本阶段引入。

**决策（用户拍板方案 A）**：保持执行自动保存行为；执行触发的保存 **toast 静默**（`save(true)`），避免每次执行都弹「已更新」；手动保存（按钮 / `⌘S`）仍有提示。此决策已写入 `DEVELOPMENT_PLAN.md` 4.5。

**状态**：已按方案 A 实现

## 二、技术缺陷（自查 / 类型检查暴露，均已修复）

### #17 文本解析注释剥离截断 URL 与颜色值

**现象**：`Referer: https://api.example.com/orders` 解析成 `https:`，`X-Color: #ff0000` 值变空。

**根因**：第一版用 `replace(/#.*$/, "").replace(/\/\/.*$/, "")` 剥离注释，`//` 和 `#` 出现在值中间（URL、色值）时被连带截断——正是最常粘贴的两种值。

**处理**：只识别**整行**注释（行首 `#` / `//`），按首个分隔符切分，`https://…`、`Bearer a=b`、`#ff0000` 全部保留；往返序列化验证稳定。

**状态**：已修复

---

### #18 后端预存 TS 收窄错误（batch-debug）

**现象**：`pnpm check` 报 `endpoints.ts` 内 `context` possibly undefined。

**根因**：`worker()` 是提升的函数声明，不继承 `if (!context) return` 建立的窄化（对 `const` 也如此——TypeScript 对提升声明保守处理）。**该错误在我改动前就存在**（原文件同样代码结构），但阻塞了类型检查。

**处理**：在 worker 前先 `const projectId = context.project.id`。

**状态**：已修复（顺手修复存量问题）

---

### #19 JSX 属性之间不能放 `{/* */}` 注释

**现象**：`defaultEnvironmentId={...}` 属性后插注释，`pnpm check` 报 TS1005。

**处理**：注释移到元素上方。

**状态**：已修复

---

### #20 `null` 不能赋给 `string | undefined` 属性

**现象**：`CaseDialog` 的 `defaultEnvironmentId` 收到 store 的 `string | null`。

**处理**：调用处 `?? undefined` 归一。

**状态**：已修复

---

### #21 三元表达式不能 `as const`

**现象**：`(isHeader ? "header" : "jsonPath") as const` 报 TS1355。

**处理**：改显式 `const type: AssertionType = ...`。

**状态**：已修复

---

### #22 保存为用例后响应被清空

**现象**：`openCase` 无条件 `setResult(undefined)`，导致刚保存为用例、用例自动加载后，生成它的那条响应消失，看起来像丢了结果。

**处理**：`openCase(testCase, keepResult)`，保存为用例场景传 `true`；常规加载用例仍清空（存量快照不是当前响应的来源）。

**状态**：已修复

## 三、保存语义设计决策（需保留，勿当 bug 修）

### #23 用例态执行不落盘（与调试态刻意相反）

**行为**：加载用例后修改请求或断言，点「执行用例」时按**屏幕版本**试跑（`executeCase` 接受 `request` / `assertions` 覆盖参数），磁盘上的用例不受影响。

**根因/意图**：与调试态「执行前隐式保存」相反——用例是回归资产，试跑不该污染存盘版本；要持久化必须显式点「保存用例」。

**风险提醒**：两条行为不对称且都是有意为之，已写入 `DEVELOPMENT_PLAN.md` 4.5。后续改动若同时动这两处，注意保持语义或先改文档。

**状态**：已确认保留

## 四、协作与流程教训

### #24 先实现后确认批次优先级，未能使用 question 工具

**现象**：P1 全量 7 周、三大块，需要拆分批次。我曾三次尝试用 `question` 工具确认范围，工具在当前环境报 schema 错误不可用，最终按「价值最高 + 是 P2 前置依赖」自行决定先做接口用例+断言。

**教训**：不可用的工具不等于可以跳过确认——本次方向恰好对（用例是场景/套件的依赖），但若选错批次，一周的工作方向性返工。后续遇到同类情况应先在文字里明确「默认方案 + 原因 + 可替换选项」再动手。

**状态**：流程教训
