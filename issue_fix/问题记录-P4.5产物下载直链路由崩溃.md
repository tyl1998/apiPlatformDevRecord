# P4.5 产物下载直链启动崩溃

## 现象

`./start.sh` 启动后 API 进程立即崩溃（`.dev-logs/api.log`）：

```
Error: Wildcard must be the last character in the route
    at Router._on (find-my-way/index.js:282)
    ...
    at runnerRoutes (src/routes/runners.ts)
```

worker / scheduler / web 正常，只有 API 起不来——`runnerRoutes` 是它独有的一组路由。

## 根因

`GET /runner/artifacts/*/download`（fs 驱动的产物下载直链，P4.5-7）把通配符 `*` 写在了
路由**中间**、后面还跟着字面量段 `/download`。find-my-way（Fastify 5 的路由器）硬性要求
通配符必须是路由的最后一段，`_on` 在注册阶段直接抛错，整个插件加载失败、进程退出。

顺带发现同一 handler 里还有第二个潜伏 bug：取 key 用的是

```ts
/^\/runner\/artifacts\/(.+)\/download$/.exec(request.raw.url)
```

锚定结尾的正则去切 `request.raw.url`——但 raw url 带着**整个 query string**
（`?expires=…&token=…`），`$` 永远匹配不上 `/download`，key 恒为空、恒 403。也就是说即使
路由能注册成功，fs 驱动的下载直链也一次都通不了（此前未暴露：P4.5-11 前没有调用方，
P4.5-7 计划里写的「手工拼 token 可验」实际验不了）。

## 修法

`routes/runners.ts` 下载直链一处改动：

1. 路由注册改为 `/runner/artifacts/*`（**结尾通配**，URL 对外形状不变）；handler 从
   `request.params["*"]` 里剥掉 `/download` 尾巴得到 storage_key。
2. 不再读 `request.raw.url`。find-my-way 对通配参数**整体解码**：
   - `presignGet` 生成的 `encodeURIComponent(key)` 形态（`%2F` 编码斜杠）参数解码后是
     完整 key；
   - 中间代理把 `%2F` 改写成字面 `/` 的形态同样命中结尾通配；
   两种形态归一成同一个 key，签名校验（HMAC 绑完整 key）对两种写法都是同一个答案。
3. 无 `/download` 尾巴的请求得到空 key，走既有的 403 分支，无新增路径。

已在 find-my-way 9.7.0 与 Fastify 5 上用 `app.inject` 实测三种形态（编码斜杠 + query、
字面斜杠 + query、无尾巴）匹配结果全部正确；`pnpm check` 通过。

## 状态

已修复。原「等待用户重启 API 后按 P4.5-7 的手工拼 token 流程复验下载直链」——
**已随 2026-09-03 P4.5 验收通过关闭**。
