# 侧边栏小屏溢出不可见 + 无收起功能

用户发现（2026-09-07）：侧边导航栏在小屏幕（矮窗口）下，溢出的部分没办法看到；
另外侧栏没有收缩功能，宽屏上占 210px 不肯让位给内容区。

## 1. 矮窗口下导航溢出不可见

- **现象**：把浏览器窗口高度压到小于侧栏内容（尤其项目侧栏 13 个导航项 + 4 个
  分组标题 + 头部 + 底部退出）时，底部的导航项和退出按钮被直接裁掉，无滚动条、
  无任何可达路径。
- **根因**：`.sidebar` 自身 `overflow: hidden`（壳层裁剪），而 `.sidebar nav`
  没有 overflow 规则——设计系统规则 5「壳拥有视口、只有 `.content` 滚动」被
  实现成了「侧栏内容也不滚动」，窗口矮于内容时溢出即静默消失。
- **修法**：`.sidebar nav` 局部滚动（`overflow-y: auto` +
  `overscroll-behavior: contain`），滚动条收窄（Firefox `scrollbar-width: thin`；
  WebKit 自绘 10px thumb 用 `--line-strong`），`scrollbar-gutter: stable` 防止
  出现滚动条时内容跳位。规则 5 指**页面级**滚动条（`.content` 拥有页面滚动）；
  侧栏列表的局部滚动与工作台侧栏、日志框是同一条纪律，不违背它。退出按钮
  （`sidebar-foot`）随 flex 布局保持常驻可见，nav 独自滚。940px 顶栏模式下
  nav 回到 `overflow: visible`（平铺换行，不滚动）。
- **状态**：已修复。

## 2. 侧栏无收缩功能

- **现象**：宽屏上侧栏恒 210px，没有收起成图标栏的模式；小笔记本上内容区
  被挤窄。
- **根因**：从未实现——壳层只有一个固定 `--shell-w` 轨道。
- **修法**：新增收起态（≥940px 桌面 rail 专用）：
  - `--shell-rail-w: 56px` token；`.console[data-collapsed]` 属性选择器一处
    声明同时驱动 grid 轨道与侧栏排版（避免「轨道换了内容没换」的半收起态）。
  - `src/stores/sidebarStore.ts`（zustand）：偏好进 localStorage
    （`apitest.sidebar.collapsed`）而非账号偏好接口——屏幕摆放偏好不是身份
    偏好，同一人在大屏与小屏笔记本想要不同默认值。`useSidebarCollapsed()`
    把宽度并进结果（940px 以下恒 false，顶栏模式没有可收起的栏）。
  - `src/components/SidebarControls.tsx`：`SidebarToggle`（PanelLeftClose /
    PanelLeftOpen，ghost 造型，Tooltip + aria-label + aria-expanded）与
    `IconNavButton`（收起态的导航图标按钮，Tooltip 补回被藏的文字标签，
    0.1s 与 `Tip` 同档）。
  - 收起态排版（design-system.css）：组标题换成 4px 分隔短横（10px 居中、
    `--line-strong`）；导航项居中成方块；lockup 只留 mark；返回主页图标化；
    sidebar-foot 竖排（退出 + 展开开关）。开关两态都住在 sidebar-foot 不
    挪窝——收起后展开键换位置，用户就得重新找它。不上右上角悬浮：
    lockup-name 是 truncate，长名会伸到悬浮按钮底下。
  - 940px 媒体查询块对 `[data-collapsed]` 显式归零（React 的 matchMedia 与
    CSS 媒体查询在跨断点瞬间可能差一拍；归零块保证顶栏模式两态同形，不出现
    「56px 宽的顶栏」）。
  - `ProjectShell`、`GlobalApp`、`theme-preview` 三处同步（样式参考页与线上
    共用同一套原语，防止漂移）。
- **边界**：i18n 补 `nav.collapse` / `nav.expand` 双语；深浅两模式共用同一
  token（无新增颜色，`--line-strong` 既有）。
- **状态**：已修复。

## 3. 收起/展开点击白屏（2026-09-07 当晚复验发现）

- **现象**：点击收缩或展开按钮，整个页面变白（React 整棵树卸载）。
- **根因**：`useSidebarCollapsed` 写成 `useSidebarStore(...) && useIsWideViewport()`
  的短路形式。`collapsed` 为 false 时 `&&` 右侧被短路，`useIsWideViewport`
  内的 `useState`/`useEffect` 不执行；点击收缩把布尔翻成 true 后右侧 hook
  开始执行，同一组件两次渲染的 hook 数量不一致，React 按规则卸载整棵树。
- **修法**：hook 无条件调用，布尔只参与最后计算：
  `const collapsed = useSidebarStore(...); const wide = useIsWideViewport();
  return collapsed && wide;`
- **状态**：已修复。
