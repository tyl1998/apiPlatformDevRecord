# P3 验收缺陷（第二轮）

用户手动验收 P3 报告页与各资源列表时反馈的问题。前五项为报告页（原「套件报告」）
的界面缺陷与改名决策，第六项为列表分页缺失。触发源/报告标识等设计背景见
`DEVELOPMENT_PLAN.md` 第六节。

## 1. 概览卡片表头文案与数据冗余

- **现象**：报告详情顶部状态概览最右侧一项，表头显示「1/1 个成员通过」，下方数据值
  又是「1/1」——动态数据写进静态表头，语义重复且不符合常规设计。
- **根因**：`SuiteReportDetail` 的 Readout 把 `t("suites.memberSummary", { success,
  total })`（本身就是一句带数字的完整文案）当 label 用，值才是 `successCount/total`。
- **修法**：label 改为静态文案 `suiteReports.memberPass`（「成员通过数」/「Members
  passed」），数字只留在值里。成员明细面板头上的 `memberSummary` 保留——它是标题旁的
  动态注释，不是表头。
- **状态**：已修复。

## 2. 「标识」区域单列布局，宽屏空间利用率极低

- **现象**：桌面端「标识」信息模块是单列键值对（标签一行、数据一行），右侧大面积
  留白，页面被无意义地纵向拉长。
- **根因**：`.definition-grid` 是 `flex-direction: column`，每个键值对占两行、独占
  整行宽度；8 个字段把面板拉到 16 行以上。
- **修法**：`.definition-grid` 改为 Grid 三列（≤940px 两列、≤700px 单列），键值对
  成为紧凑单元格；同时补上 `dd { margin: 0 }`（浏览器默认给 `dd` 40px 左缩进，值
  不在标签正下方）。`DataSourceDetail` 的连接配置用同一套类，一并受益。
- **状态**：已修复。

## 3. 核心数据被挤出首屏

- **现象**：「成员明细」表被拉长的「标识」区域挤到视口底部，要看哪个成员失败得先
  滚一屏。
- **根因**：即缺陷 2 的纵向空间浪费；概览卡片与标识段合计超过一屏。
- **修法**：随缺陷 2 的多列布局解决——标识段从 16+ 行收到 3 行左右，成员明细回到
  首屏。
- **状态**：已修复（随缺陷 2）。

## 4. 未使用通用导航；「返回流程列表」按钮文案与去向都不对

- **现象**：报告详情没有走顶栏面包屑，页面右上角自带一个「返回流程列表」按钮——
  从报告页返回的应是报告列表而不是流程列表。
- **根因**：`ProjectShell` 的 `detailOpen` 只覆盖 endpoints/flows/suites/data-sources
  四个详情路由，`suite-reports/:executionId` 不在其中，面包屑只显示到「套件报告」；
  详情页于是自带 `onBack` 按钮，文案直接复用了 `flows.backToList`。
- **修法**：面包屑补上报告详情一级——`{项目名称}/报告列表/{报告名称}`，报告名由详情
  页经 Outlet context（`DetailCrumbContext`）推给外壳，加载中回落「当前报告」；
  删除页面自带的返回按钮与 `onBack`，加载失败态也不再需要返回动作（面包屑的中段
  就是返回报告列表的链接）。
- **状态**：已修复。

## 5. 「套件报告」改名「报告列表」

- **现象/决策**：导航与页面标题显示「套件报告」，后续要接入仓库（单测/流水线）的
  报告类型，名字提前泛化。
- **修法**：i18n `nav.suiteReports` / `suiteReports.title` 改为「报告列表」/
  「Report list」；路由 `/suite-reports` 与 API 路径不动（URL 稳定，只改展示名）。
- **状态**：已实现。

## 6. 接口列表、环境管理、数据源、Mock、套件成员解析列表均无分页

- **现象**：五个列表一次渲染全部行，数据量上来后页面无限拉长。
- **根因**：`GET /endpoints`、`GET /data-sources`、`GET /mocks` 只返回全量数组；
  环境管理页渲染的是全局 store 的完整清单；套件页的成员解析预览一次性展开全部
  成员（上限 200）。
- **修法**（按数据源分两类）：
  - **服务端 opt-in 分页**：三个列表路由加可选 `page`/`pageSize`——不传 `pageSize`
    仍返回全量（项目 store、流程节点选择器、Mock 快照来源都依赖全量契约，不能默认
    截断）；列表页改走 `api.endpointsPaged` / `dataSourcesPaged` / `mocksPaged`，
    底部 antd 分页器（20/50/100、真实 total、超 5 页出快速跳转）。
  - **就地分页**：环境管理页（store 全量清单是全应用共享的数据源，分页只属于表格
    展示）与套件页成员列表（手动清单 + 解析预览，数据已整份在手；新一份解析结果
    回到第一页，手动加成员翻到最后一页让「刚加的」立即可见，删到本页最后一行钳回
    最后一页）。
- **状态**：已实现。报告成员明细有意不分页（边界 14：通读「哪几个失败了」不该翻页），
  维持原决策。

## 附：修复验证约定

按项目约定未做自动化/浏览器验证，行为验收由用户手动进行（重启服务后走查：
报告列表改名与面包屑、报告详情首屏与标识多列、五个列表的分页交互）。
