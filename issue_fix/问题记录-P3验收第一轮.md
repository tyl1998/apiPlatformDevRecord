# P3 验收缺陷（第一轮）

用户手动验收 P3（调度 / 报告 / 告警）发现的问题。前四项为已修复的确定缺陷，
第五项待复现。触发源/报告标识等设计背景见 `DEVELOPMENT_PLAN.md` 第六节。

## 1. 点击「创建调度」白屏

- **现象**：定时调度页点击「创建调度」按钮，页面白屏。控制台报
  `KeyValueEditor.tsx:120 Uncaught TypeError: pairs.filter is not a function`。
- **根因**：`Schedules.tsx` 把变量覆盖的状态初始化成 `fromPairs([])`（一个
  `{}` 对象），而 `KeyValueEditor` 的 `pairs` 形参是 `Pair[]`。编辑抽屉一打开
  就把 `{}` 传进去，`pairs.filter` 不存在，渲染期抛错且无 ErrorBoundary，
  整棵 React 树卸载。`tsc` 此前已报出该处 5 个类型错误，属「类型错误上线」。
- **修法**：状态类型改为 `Pair[]`，初始化 `useState<Pair[]>([])`；新建分支
  `setVariables([])`；保存时仍 `fromPairs(variables)` 转回对象。
- **状态**：已修复。

## 2. 运行套件白屏，且执行完成后一直显示「执行中」

- **现象**：套件页点击「运行」，页面白屏；套件实际已在后台执行完成，
  界面冻结在崩溃前的「执行中」状态。控制台报
  `SuiteReports.tsx:26 Uncaught TypeError: Cannot read properties of undefined (reading 'charAt')`，
  调用栈指向 `SuiteRunDrawer.tsx:114 triggerLabel(t, run.triggerSource, ...)`。
- **根因**：`start()` 用 202 入队响应乐观构造运行对象 `{ ...queued,
  executionSteps: [], runs: [] }`，但入队响应是 `suite_executions` 的形状，
  **不带** `execution_index` 上的触发三列（`triggerSource` 等只有详情路由
  join 后才返回）。运行抽屉标识段立即读到 `undefined.charAt`，渲染期崩溃，
  整棵树卸载后不再有任何事件/重取驱动界面更新，「执行中」是冻结的残影，
  不是数据库状态（查库全部已是终态）。
- **修法**：两处防御——`start()` 补 `triggerSource: "manual"`；
  `triggerLabel` 的 `source` 形参改为可空，缺省按 manual 渲染（其它不含
  触发列的调用形状也不再脆断）。
- **状态**：已修复。

## 3. 编辑调度保存必然 500

- **现象**：编辑已存在的调度并保存，接口 500（用户尚未走到这一步，走查发现）。
- **根因**：`routes/schedules.ts` PUT 处理器在 `const before = existing.rows[0]`
  声明**之前**就引用了 `before.timezone`（TDZ），`ReferenceError` 未被捕获，
  直接 500。
- **修法**：把 `before` 的声明移到 `validateSchedule` 调用之前。
- **状态**：已修复。

## 4. 套件报告成员无证据入口

- **现象**：报告详情页成员明细只是一张静态表，看不到某成员的请求快照 /
  流程步骤树；用户期望点成员弹抽屉（与运行抽屉同款交互）。
- **修法**：`SuiteRunDrawer` 导出 `MemberEvidence` 与 `MemberRow`；报告页
  成员行按 `httpExecutionId / childIndexId / error` 判定可点击，点击后拉
  单执行快照（用例成员）并弹抽屉，证据渲染与运行抽屉共用同一实现。
- **状态**：已修复。

## 5. 进入套件未改动，退出时提示「有更改」

- **现象**：进入「套件测试1」不做任何修改，退出时弹「未保存更改」确认框。
- **排查**：脏检测对 `suite` 与 `draft` 做 canonical（键排序 + trim）后比较，
  当前库里该套件的 selection/execution 与页面草稿形状一致，静态推演不会置脏；
  成员引用三条全部存在（无 staleDropped 路径）。怀疑与缺陷 2 的崩溃残影或
  当时的悬空成员有关（悬空成员按设计会置脏并显示黄色提示）。
- **状态**：已关闭（2026-08-28 验收通过，缺陷 2 修复后未再复现）。

## 6. 数据看板「定时任务数」一直显示「未启用」

- **现象**：数据看板的定时任务数固定显示「未启用」占位文案。
- **根因**：P3-6 已让 `GET /dashboard` 返回真值 `scheduleCount`（含停用），前端
  `GlobalApp.tsx` 的读数没有接上，仍是占位分支。
- **修法**：读数改为 `data.scheduleCount`（CI 任务读数仍占位，属 P4.5 范围）。
- **状态**：已修复。
