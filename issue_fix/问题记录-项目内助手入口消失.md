# 项目内顶栏的站内助手入口消失（P14-1 访问闸 × 助手槽位查找）

> 2026-09-21 用户实测：进入项目后，顶栏右上角的站内助手入口（头像圆钮）不见了。
> 当时怀疑与同批的小屏 CSS 改动有关，排查后确认无关——是 P14-1 访问闸与
> `AssistantDock` 槽位查找的时序问题。

## 现象

- 进入/切到某个项目后，顶栏 `.topbar-actions` 里只有项目切换器，`#assistant-topbar-slot`
  空空（`.assistant-topbar-slot:empty` 规则让它不占宽），助手入口不出现。
- 在项目内再点一次左侧导航（路径变化）后，入口会回来。
- 非助手相关的样式都正常；`.assistant-entry` 自身没有任何规则被改动。

## 根因

两处代码的时序叠加：

1. `ProjectShell.tsx:191`（P14-1 访问闸）：`identity === undefined` 时直接
   `return <div className="console-gate" />` —— **整个壳（含顶栏与槽位）都不渲染**，
   身份请求落地后才渲染真正的 console。
2. `AssistantDock.tsx:574`：槽位查找是
   `useEffect(() => setEntrySlot(document.getElementById("assistant-topbar-slot")), [location.pathname])`
   —— 只在 **pathname 变化那一次 commit 之后**找一次。

于是进入项目时的顺序是：路径已变 → 该次 commit 渲染的是访问闸（没有槽位）→ effect 找不到
槽位（`entrySlot` 置 null）→ 身份请求回来、console 与槽位挂上 → **但 pathname 没变，
effect 不会再跑一次** → 入口再也不挂载，直到下一次导航。

## 修法

`AssistantDock.tsx:570-587`：把「只找一次」改成「槽位后到时短重试」——每 200ms 找一次、
最多 20 次（约 4s，足够身份请求落地），找到即停；离开壳的页面（登录页 / 非成员落地页）
空转到上限即结束，不常驻轮询，也不引入 MutationObserver 那种全站 DOM 回调。

```ts
const find = () => {
  const node = document.getElementById("assistant-topbar-slot");
  setEntrySlot((previous) => (previous === node ? previous : node));
  if (!node && ++tries < 20) timer = window.setTimeout(find, 200);
};
find();
```

**备选（未采用，留给 P14-1 归属方）**：让访问闸只闸正文、保留壳与顶栏（槽位就不会缺席，
也不会在进项目时整壳重挂）。这条要动 `ProjectShell` 的闸门渲染形态，与 P14-1 正在改的
文件重叠，故本轮不动。

**另一条待排除的可能**：`availability === "disabled"`（助手探测/会话列表回 404）时整个
入口 `return null`。若修后入口仍不来，按这条查网络面板（`probeAssistantAvailability`
与 `GET conversations` 的状态码）。
