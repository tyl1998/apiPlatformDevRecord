# 计划详情未执行计数窄屏溢出

用户发现（2026-09-09）：测试计划详情页头部统计行（「0 条未执行 / 通过 14 /
失败 2 / 阻塞 3 / 跳过 1」）在缩小窗口后没有小屏兼容——四态计数直接压过
格线挤进相邻统计格。

## 现象

- 把窗口从宽屏逐渐收窄，「N 条未执行」这枚 Readout 值位里的四枚 Status
  chip（`通过 14 失败 2 阻塞 3 跳过 1`）越出本格右缘，压过 `border-left`
  分隔线盖到右侧「负责人」格上；≤560px 两列网格下则压过半格边线，320px
  级宽度时顶出 `.readouts` 容器（横向溢出，违反不变量「任意宽度无横向
  页面滚动」）。

## 根因

- `.readout-marks`（`TestPlans.tsx` 计划详情头部，2026-09-09 第三轮加入）
  是 `display: inline-flex; gap: 10px`，**无换行**。四枚 chip 自身
  `white-space: nowrap`（`.status`，词不拆是正确设计），整行 min-content
  约 260px。
- 而值位宽度随断点收窄：>560px 时 `.readouts` 五枚 `flex: 1 1 0` 平分
  （约 1500px 视口以下每枚就不足 260px），≤560px 时是两列网格的半格
  （375px 视口约 147px）。
- `.readout` 的 `min-width: 104px`（≤560px 显式归零）只约束**盒子**宽度，
  管不住内容溢出——flex 布局不把 nowrap 内容计回item 尺寸，溢出即静默
  越界（`.readout` 没有 overflow 规则，不裁剪也不滚动）。

## 修法

- `design-system.css` 的 `.readout-marks` 加 `flex-wrap: wrap`，行距收一档
  （`gap: 4px 10px`）：空间不足时 chip **整枚**掉行（掉行单位是「词 N」，
  词不拆），宽屏单行形态不变。无 TSX 改动——类名与结构原样。
- 换行后该 readout 变高时，同行其余 readout 随 flex 默认 stretch 拉齐，
  分隔线仍然连续，不出现锯齿断线。

已修复。

## 涉及文件

- `apitest-web/src/design-system.css`：`.readout-marks` 补 `flex-wrap: wrap`
  与行距/列距分档（4px / 10px）。
