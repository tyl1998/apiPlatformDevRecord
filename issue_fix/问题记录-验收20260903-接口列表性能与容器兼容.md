## ① 接口管理页加载慢，`/executions` 一次 254KB

**现象**

打开接口管理页明显变慢；网络面板里 `GET /api/v1/projects/:id/executions?pageSize=200`
一次拉回约 254KB，且**每次翻页 / 改筛选都重拉**。

**根因**

列表页为了画「最近运行」条与状态/耗时列，前端把整页接口与 200 条最近执行**并行全量**
拉回，再在内存里按 endpointId 分组（`EndpointList.tsx` 的 `runsByEndpoint`）。执行记录
带完整的请求/响应快照（`mapExecution` 全字段），200 条就是几百 KB；执行数一涨，这个
数字线性变坏。列表页本来只需要「每个接口最近一次的状态与耗时」两个标量。

**修法**

- 服务端（`routes/endpoints.ts` 的 `GET /endpoints`）：`LEFT JOIN LATERAL` 按
  `executions_endpoint_created_at_idx` 随行带出每个接口最近一次执行的
  `last_status` / `last_duration_ms`（`source <> 'flow_step'`，与旧前端拉法同口径），
  分页与否同一条 select。
- 前端（`EndpointList.tsx`）：删掉 `api.executions({pageSize:200})` 拉取、`recent`
  state、`runsByEndpoint` 与「最近运行」列（用户确认不要）；耗时/状态列改读接口行上
  的 `lastStatus` / `lastDurationMs`。`api.ts` 的 `Endpoint` 类型补这两个可选字段。

**状态**：已修。

## ② 仓库模式容器运行必失败：`docker run` 退出码 125

**现象**

容器档任务在 script 阶段失败，日志尾部：

```
docker: Error response from daemon: --storage-opt is supported only for overlay over xfs with 'pquota' mount option
Run 'docker run --help' for more information
[runner] report: no files matched "./allure-results"; producing zero cases
[runner] job finished: failed (script exited with code 125)
```

**根因**

`buildDockerRunArgs` 无条件带 `--storage-opt size=<disk_limit>`，而该旗标只在特定存储
驱动上成立（overlay2 需要 xfs backing + `pquota`；Docker Desktop / OrbStack / 大多数
自建 daemon 都不满足）。daemon 在 create 阶段直接拒绝，CLI 退 125——那是「docker run
自己失败」，被当成脚本失败上报了。本机 Docker 29.4.0（overlay2）实测复现：带
`--storage-opt size=10g` 退 125，去掉即成功。

**修法**

两条通道（`apitest-runner/src/executor/container/`）同一条纪律：**撞上即降级重试一次，
进程内记住，之后的 job 直接走无 size 路径**——磁盘限额退化为无上限，CPU / 内存限额
不受影响，降级原因写进 job 日志。

- `runtime.ts`：共享的拒绝特征 `STORAGE_OPT_REJECT = /storage-opt|pquota/i`（CLI 与
  Engine API 的措辞都在里面）。
- `cli.ts`：`run` 拆成 `runOnce(storageOpt)`，`docker run` 退 125 且 stderr 命中特征时
  去旗标重跑一次；`buildDockerRunArgs` 增加可选 `{storageOpt: false}`。
- `api.ts`：`createContainer` 的 400 报错命中特征时去掉 `HostConfig.StorageOpt` 重建；
  `buildCreateBody` 增加同款可选参数。

按进程内缓存而不是启动探测：探测要真起一个容器才有结论，为它付一次拉镜像不值得。

**状态**：已修。

## ⑤ 报告分享页点开 case / 流程成员没有反应，无抽屉

**现象**

套件报告分享链接打开后，成员明细里点击用例或流程成员行，没有任何反馈——站内报告
详情页同样的点击会弹证据抽屉。

**根因**

`SuiteReportDetail` 的 `canOpenEvidence` 在 `publicView` 下恒为 false（成员行连
`data-clickable` 都没有）：成员证据（用例的执行快照、流程的步骤树）原先只有按登录
用户鉴权的项目内路由，公开页拉不到，于是当初直接关掉了抽屉。仓库执行报告的分享页
（allure 用例表）不受影响——它的抽屉数据就在公开载荷里。

**修法**

证据按 token 放出来，归属由服务端收紧：

- 服务端（`routes/reportShares.ts`）新增三个公开端点，鉴权从「项目成员」换成
  「持有 token」，归属判定走**证据闭包**——从该套件执行的 index 出发，沿
  `execution_steps.child_index_id` 递归可达的全部 index；闭包之外的行一律 404（token
  换的是「这份报告的证据」，不是「这个项目的执行历史」）：
  - `GET /public/report-shares/:token/executions/:executionId` → 用例成员快照；
  - `GET /public/report-shares/:token/flow-steps/:indexId` → 流程成员整次执行（服务端
    就地完成站内的两跳）；
  - `GET /public/report-shares/:token/step-children/:stepId` → 容器步骤内层证据。
- 前端：`SuiteReportDetail` 收 `shareToken`，成员行恢复可点；`MemberEvidence` /
  `FlowMemberSteps` / `StepEvidence` / `NestedStepList` 串一个可选 `shareToken`，传了
  它取数走公开端点，站内路径不变。`publicView` 只继续关分享按钮（创建分享要 write）。

**状态**：已修。
