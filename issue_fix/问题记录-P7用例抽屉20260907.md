# 问题记录 — P7 用例库（2026-09-07 验收反馈，多轮）

> 范围：P7-2 用例 CRUD / P7-3 树视图落地后的使用反馈。第一轮三项集中在用例详情
> 抽屉的「前置条件 / 步骤」编辑区；第二轮两项为树视图布局重做（表内树 → 经典
> 左右分栏）与抽屉编辑器改版。均属交互缺陷，无后端与数据面改动。

## ① 步骤区块两列输入框含义不明

- **现象**：每行步骤是两个平级文本框，上方无表头列名；框内有内容时 placeholder
  不可见，无法区分哪个是操作步骤、哪个是预期结果。
- **根因**：行内步骤表借用了 KeyValueEditor 的 `kv-row` 形状，而 kv 编辑器的两列
  天然对称（key/value），步骤/预期是**语义不同**的两列——只靠 placeholder（且
  只在空行可见）不足以表达列义。尾随空行的预期列 placeholder 还是空串。
- **修法**：步骤区块顶部加**常驻两列表头**（操作步骤 / 预期结果）；表头与数据行
  共用同一份 inline 网格模板 `STEP_ROW_GRID`（序号 18px / 步骤 1fr / 预期 1.4fr /
  删除 30px）——`.kv-row` 每行是独立 grid、auto 列各自按内容算宽，不钉死宽度
  表头与数据行会错位。placeholder 统一为「操作步骤 / 预期结果」并覆盖全部行
  （含尾随空行）；空行原「添加步骤」专属占位撤销（虚线边框已表达「在此新增」）。
- **状态**：已修复（2026-09-07）。

## ② 步骤长文本被单行框截断

- **现象**：步骤的预期列常包含完整接口调用信息（URL + 参数），单行输入框右侧
  溢出不可见，无法核对参数。
- **根因**：步骤/预期用单行 `<input>`，`.input` 固定 34px 高、不换行。
- **修法**：步骤与预期改 `AutoGrowTextarea`：`rows=1` 起步、按 `scrollHeight`
  自动长高、长内容自动换行；resize 手柄关闭（手动拖出的高度会在下一次内容变化
  时被滚动高度覆盖，留着只会误导）。只读（viewer）视角同样受益——完整内容可见。
- **状态**：已修复（2026-09-07）。

## ③ 前置条件固定两行高，挤压步骤区块

- **现象**：一条单行脏数据（如 `wqe`）占据两行高的多行框，抽屉纵向空间被浪费，
  步骤区块被大幅下推。
- **根因**：前置条件写死 `rows={2}`，高度与内容无关。
- **修法**：与 ② 共用 `AutoGrowTextarea`——空/短内容只占一行高，长内容自动长高；
  顺带补了 placeholder 示例（「如：已登录且有可用的收货地址」）。
- **状态**：已修复（2026-09-07）。

## 第二轮反馈（同日稍后）

## ④ 树视图「表内树」层级与数据挤在一起，导航不成立

- **现象**：模块行与用例行混在同一张表里逐级展开，用户反馈「还是抽象」——层级
  清晰度与数据对齐都不如经典的左右分栏；点目录看不到「只有这个目录下的用例」。
- **根因**：首版借用了 RepoCaseTree 的表内树形状（系统 → 接口 → 用例两层层级
  且列宽固定，天然适配）；文本用例的树是**多级自由结构 + 用例本身字段多**，
  塞进同一张表后序号/勾选/路径列全要为层级让位。
- **修法**：重做为经典左右分栏——左侧常驻模块树（`.spec-tree`：纯导航、sticky、
  子树计数、选中态 selected+accent 左缘、940px 以下退化为顶部横条），右侧只专注
  用例表；点目录 = path 前缀筛（含子级，与节点计数同口径），再点取消。视图切换
  只剩**脑图（分栏，默认）/ 列表（全宽平表）**。首版的单模块懒载/截断说明/代数
  作废机制整体撤销（用例永远走右表服务端分页）；`ModuleCreateModal` 抽成共享
  组件，树面板与抽屉同一套「新建模块」。
- **状态**：已修复（2026-09-07）。

## ⑤ 抽屉编辑器宽度与步骤表观感

- **现象**：640px 抽屉装不下步骤/预期两列的长文本；步骤区仍是一堆散框，读不出
  「这是一张两列表」。
- **根因**：宽度按 Mock 详情抽屉惯例取固定 640px；步骤行复用 kv-row 的散框
  形态（无外框、无分隔线、输入框各自带边框）。
- **修法**：抽屉宽度改**页面 70%**；步骤区块改 `.steps-table`——容器带边框、
  表头 raised 底（与全站 `.grid th` 同字级字距）、行间细分隔线、输入框静息
  无边框（聚焦恢复实线 + ring）、行顶对齐（多行内容时序号与删除键跟着首行）。
- **状态**：已修复（2026-09-07）。

## 第三轮反馈（分栏落地后，抽屉细节）

## ⑥ 步骤表头与输入框列错位、字号小无边界

- **现象**：「操作步骤 / 预期结果」表头与下方输入框在横向上错位；11px 小字 +
  极浅的 raised 底让表头看起来像悬浮文本。
- **根因**：两个错位源——① textarea 自带 `var(--s3)`（12px）横向内边距，输入
  文字相对框边缘内缩，而表头文字贴列起点，差 12px；② 表头样式抄了 `.grid th`
  的 11px/ink-3（英文表头的小字惯例），在只有两列的行内编辑区太小。
- **修法**：表头列名加 `steps-col-label`（`padding-left: var(--s3)`）与输入框
  **内文字**对齐；表头升到 12px / 600 / ink-2。
- **状态**：已修复（2026-09-07）。

## ⑦ 步骤序号与多行输入框垂直错位

- **现象**：序号（1、2、3…）悬在行上部，与输入框第一行文字顶部不齐。
- **根因**：`.steps-table .mono` 只给了 8px 顶距，没钉行高——序号默认行高
  （~14px）与 textarea 首行行高（1.6×13≈21px）不一致，基线差 ~4px。
- **修法**：`padding-top: 9px; line-height: 21px`（= textarea 的 8px 内边距 +
  1px 边框 + 首行行高），序号与首行文字基线对齐。
- **状态**：已修复（2026-09-07）。

## ⑧ 长文本被截断 + 多余竖向滚动条

- **现象**：预期列输入长接口路径（`/api/v3/...`）后输入框高度不变、出竖向滚动
  条，内容看不全。
- **根因**：全局 `* { box-sizing: border-box }`（design-system.css:105）下，
  `height = scrollHeight` 的自动长高**永远差上下边框 2px**——scrollHeight 不含
  边框而 border-box 的 height 含，内容常溢出一线 → 永久滚动条 + 末行被裁。
- **修法**：量出上下边框和（`offsetHeight − clientHeight`）补进高度，不写死
  数值；修后内容完整可见、无滚动条。
- **状态**：已修复（2026-09-07）。

## ⑨ 前置条件与步骤区块间距过紧

- **现象**：前置条件框底部与「步骤」标题之间的间距太小，多层块级元素挤在一起。
- **根因**：`.form-grid .field { margin-bottom: 0 }`，区块间隔全靠步骤区的
  `marginTop: var(--s5)`（20px）一档。
- **修法**：间距升到 `var(--s7)`（32px）。
- **状态**：已修复（2026-09-07）。

## ⑩ 「新建模块」不应出现在用例抽屉里

- **现象**：用例编辑抽屉的所属模块字段旁内嵌「新建模块」按钮——录用例的地方
  混进了结构管理动作。
- **根因**：P7-2 时树面板还不存在，抽屉内联建模块是「手工建用例可用」的最小
  闭环；分栏落地后树面板已有常驻入口，双入口成为冗余。
- **修法**：建模块的**唯一入口收敛到左侧树面板**（脑图视图）；抽屉删除内联
  按钮与 `onModulesChanged` 链路，无模块时提示文案指路树面板；面板与抽屉的
  空态提示拆成两个 key（语境不同）。
- **状态**：已修复（2026-09-07）。

## 第四~六轮反馈（同日，视图体系重做）

## ⑪ 模块树面板不贯满高度

- **现象**：左侧「模块」框是收缩式（max-height 随内容收缩），少模块时缩成
  矮框，与右侧内容顶不齐。
- **根因**：`.spec-tree` 用 `max-height` 而非固定高度——「随内容长高」在内容
  少时等于「面板很矮」。
- **修法**：通贯式侧边栏——sticky + `height: calc(100dvh - 150px)` 钉满可视
  高度，内部自滚（`.content` 仍是唯一页面滚动容器；940px 以下退回
  max-height 220px 横条，竖屏半高空面板没有意义）。
- **状态**：已修复（2026-09-07）。

## ⑫ tree/list 平表切换冗余、「脑图」名不副实

- **现象**：分栏视图与全宽平表切换是两个列表排法；而「脑图」标签挂在分栏
  视图身上——它不是脑图。
- **根因**：P7-3 首版把「树/表两种排法」当成了视图轴，后来分栏落地后这个轴
  上只剩两种表格。
- **修法**：删除 tree/list 切换（分栏即列表视图）；「脑图」标签摘下还给真正的
  XMind 风格思维导图（`?view=mindmap`，新组件 SpecMindMap）。
- **状态**：已修复（2026-09-07）。

## ⑬ 脑图把模块树也画了进去

- **现象**：脑图视图把模块层级连同用例一起解析成思维导图——结构视图抢了
  树面板的职责，且和右表口径（当前目录的用例）对不上。
- **根因**：首版脑图以「root → 模块森林 → 用例」为骨架，把导航树当成了图
  的内容层。
- **修法**：树面板在两个视图里都常驻不动，切换只换右半；脑图解析**当前目录
  下的用例**——root = 树里点中的目录（缺省「全部用例」）→ 该目录（path 前缀
  筛，与右表同口径）的用例 → 每条用例展开 前置/步骤/预期（`tc:` XMind 用例
  约定的层级）。
- **状态**：已修复（2026-09-07）。

## ⑭ 脑图编辑与展开交互不符预期

- **现象**：节点双击进的是编辑抽屉、展开靠点节点本体、铅笔按钮悬停才现——
  「都是 XMind 格式了，预计就直接编辑了」。
- **根因**：手写 SVG 画布（自管布局 + 绝对定位 + 自绘连线）没有键盘/焦点/
  编辑的交互底座，只能把编辑动作外挂成铅笔按钮与抽屉，每个交互都是补丁。
- **修法**：脑图画布重做在 **@xyflow/react** 上（流程画布同一个库，零新增
  依赖）：平移/缩放/选中交给库，交互按 XMind 惯例——**单击选中、双击就地
  编辑**（Enter/Tab 提交、Esc 取消、失焦提交，输入框挂载即聚焦全选）、
  **⊕/⊖ 折叠用例**、Tab 加子级（根→用例、用例→步骤、步骤→预期）、Enter 加
  同级；编辑直接落库（整份 PATCH，与抽屉保存同一形状）。就地图上的新增
  （Tab/Enter 建的用例/步骤）先落占位标题再立即进入编辑。
- **状态**：已修复（2026-09-07）。

## 第七轮反馈（脑图落地后的四个缺陷）

## ⑮ 脑图内 Tab 新增后刚建的节点把用例「顶没了」

- **现象**：在脑图里 Tab/Enter 新增用例或步骤后，图上只剩当前步骤（或新节
  点），所属用例像被顶掉一样消失。
- **根因**：`pendingEdit`（建完即编辑）在**旧图**上就开输入框：步骤节点 id
  是**位置 id**（`step:<caseId>:<序号>`），Tab 插入第 N 步时旧图里就有同
  名 id（原来的第 N 步）。输入框刚挂到旧节点上，重取的新图整代替换节点
  集，编辑态被顶掉，视觉等于「新步骤顶没了用例」。
- **修法**：建节点的动作记录**目标代数**（armPendingEdit：`dataGen + 1`，
  即 onSaved 推 revision 后那次重取的 gen）；「新图就位→就地编辑」加了
  代数门——必须等创建时刻的那次响应**真正提交**（committedGen）才开输入
  框，旧 data 上的同名 id 不再触发。
- **状态**：已修复（2026-09-07）。

## ⑯ 脑图分不清哪个节点是用例、哪个是步骤

- **现象**：图上多个层级都是差不多的长框节点，没有标记说明这是 case、步
  骤、目录还是前置。
- **根因**：节点形状只靠层级位置区分（第一列=目录、第二列=用例……），
  缩放/滚动后位置线索失效。
- **修法**：每个节点带**形状徽记**（`mindmap-tag` 小 chip）：目录/用例/
  前置/步骤/预期；用例仍保留生命周期色点 + 编号 + 优先级，步骤保留序号。
  徽记中性不上色（Quiet Console：颜色只留给语义）。
- **状态**：已修复（2026-09-07）。

## ⑰ 从脑图切回列表打开用例，抽屉内容是旧的

- **现象**：在脑图里就地改了用例标题/步骤 → 切回列表 → 点开同一条用例，
  抽屉里还是改动前的旧内容（信息「错乱」）。
- **根因**：抽屉吃的是**行对象**（`editing` 存 `SpecCase` 快照）。列表行是
  当次查询的快照；脑图编辑落库后（revision 推进、列表重取）用户若在重取
  完成前点行，或从脑图直接传行对象，闭包里都是旧对象——抽屉把快照当事实。
- **修法**：`editing` 只存**意图**（`"new" | 用例 id`）；抽屉挂载时按 id 调
  `GET /spec-cases/:caseId` 现拉详情，列表行/脑图行快照一律不进抽屉。详情
  拉取中出加载行而不是空表单（空表单会被读成「用例是空的」）。
- **状态**：已修复（2026-09-07）。

## ⑱ 切换目录时脑图渲染混乱

- **现象**：左侧树切换目录后，脑图新旧两层节点叠在一起、连线错乱。
- **根因**：两个叠加因素——① 换目录只重置了展开/选中/编辑，**data 没清
  空**：新数据回来前旧图还挂在画布上，React Flow 按**节点 id** 淼合新旧两
  代节点（位置全在同一套 position 上），渲染错乱；② fitView 在画布未挂
  载/换数据时机的调用不可靠。
- **修法**：换目录时 data 归零回加载态（等价整图重挂，空图先清场再等新
  数据）；fitView 改为「data 真正换代后」触发（挂载后必然安全），换目录
  与重取两条路径都覆盖。
- **状态**：已修复（2026-09-07）。

## 第八轮反馈（⑮~⑱ 修复后复测，同日稍晚——四项均有残余）

## ⑲ 脑图 Tab 连按：标题回退 / 步骤丢失 / 双建用例（⑮ 残余）

- **现象**：脑图内 Tab 建用例后紧接着 Tab 加步骤（快速连按），刚输入的
  标题被顶回占位文本、先加的步骤只剩最后一条，个别时序下连按两次 Tab
  建出两条用例——视觉即「用例消失，只剩当前步骤」。
- **根因**：⑮ 的代数门只堵住了「编辑态开在旧图」这一个表现，落库本身仍
  是**整份快照提交**（caseToInput：标题/前置/步骤/优先级/状态全量发），
  快照取自重取前的旧图——连按时第二个请求带着旧标题/旧步骤表整份覆盖第
  一个请求的结果；「建完即编辑」要等重取落地，快动作落在重取窗口里读的
  还是旧图；keydown 无在途守卫，createCase 的 PATCH 未返回前 selectedId
  仍是 root，第二次 Tab 再建一条。
- **修法**：三件套换掉整个时序假设——① 落库改**最小提交**：只 PATCH 被
  改的字段（标题 / 前置 / 单份步骤表），服务端本就按键局部更新，整份提
  交是前端自加的覆盖源；② PATCH/POST **响应即时合入**本地 data
  （applyLocalCase：按 id 替换、新建追加、modulePath 保留行上原值），
  下一个键盘动作立刻读到服务端真值；③ 「建完即编辑」直接在乐观图上开输
  入框（节点是自己刚建的，id 即构造），原 pendingEdit 代数门机制整体删
  除。另：keydown 加 busyRef 在途守卫（动作未返回不叠加）；有筛选时新建
  用例不做乐观追加（占位标题多半不命中筛选，追进去只会闪现一帧）。
- **状态**：已修复（2026-09-07）。

## ⑳ 新增那一刻节点种类不可见、规则无处可学（⑯ 残余）

- **现象**：徽记在静息态可见，但**就地编辑态整个节点被输入框接管**——
  新增那一刻（最需要确认「我建的是用例还是步骤」的时刻）徽记恰好消失；
  Tab/Enter 会建出什么、双击能改什么，画布上没有任何提示。
- **根因**：⑯ 只修了静息态的徽记；编辑分支渲染时只留 input。键盘添加规
  则只存在于 ⑭ 的修复记录里，界面上无处可学。
- **修法**：编辑态保留徽记与步骤序号（输入框前缀，`.mindmap-input` 改
  flex 收缩让位）；画布左上加一行静态键位提示（`Tab 加子级 · Enter 加同
  级 · 双击就地编辑 · ⊕/⊖ 折叠用例`，`.mindmap-hint`：pointer-events
  不挡平移、只读视角不显示——viewer 没有键盘添加）。
- **状态**：已修复（2026-09-07）。

## ㉑ 切回列表打开用例，抽屉闪旧内容 / 表单被重置（⑰ 残余）

- **现象**：复测仍能碰到两种「信息错乱」：关闭 A 再打开 B 的头一两帧闪出

- **根因**：⑰ 的「按 id 现拉」只保证了数据源，三处时序漏洞仍在——① 抽

## ㉓ 脑图 Tab 加步骤后画布空白（白屏）

- **现象**：修复 ⑲ 后复测，Tab 建用例再 Tab 加步骤，画布一片空白（节点
  全部消失、连线全无，只剩缩放控件）；偶发部分节点消失「只剩当前步骤」
  ——⑮ 的原始症状其实是同一个病。
- **根因**：**React Flow 受控节点按对象引用判等**（adoptUserNodes 的
  checkEquality）：`nodes` 数组/节点对象引用一换，内部 measured 与
  handleBounds 整重置，节点回未测量态（`visibility: hidden`、连线因锚点
  丢失全部消失），要等 ResizeObserver 重测并 set() 通知才能恢复。而
  MindMapCanvas **每次渲染都重建 nodes 数组**，⑲ 引入乐观合入后「乐观
  换代 → loading 翻转 → 重取换代」连续多次换引用，观察器回调追不上最后
  一次重置，节点**永久卡在 hidden**（浏览器复现确认：8 个节点全
  hidden、0 连线；强制改一个节点宽度后仅该节点恢复——证明观察器活着但
  其余节点的初始回调已被换代吞掉）。
- **修法**（三层，缺一不可）：
  ① **measured 随身带回**：nodes 映射时从 `useStoreApi().getState()
  .nodeLookup` 把每个节点的 measured 复制到 user 节点上——adoptUserNodes
  见到 userNode.measured 即沿用旧 handleBounds，换代不再把节点打回未测
  量态（v12 的类型就支持 user 节点携带 measured）；
  ② **nodes 按 [graph, selectedId, edit] memo**：loading 翻转这类无关
  渲染不再触发 StoreUpdater 的 props→store 同步；
  ③ **建完即编辑的焦点重试**（顺带发现的死陷阱）：新建节点挂载瞬间还
  是未测量态（hidden），此时 `focus()` 静默失败——输入框开着却没有焦
  点，Tab 落到 document 层又被 edit 态挡掉，键盘像失灵；focusOnce 改逐
  帧重试（≤30 帧）到真正拿到焦点。
- **验证**：浏览器复现原始操作序列（点目录 → Tab 建用例 → Tab 提交 →
  Tab 加步骤）：14 节点全可见、步骤节点就位、编辑焦点链路正常，无空白。
- **状态**：已修复（2026-09-07）。

## ㉓b 模块改名 PATCH 500（新 UI 首次踩中的潜伏后端缺陷）

- **现象**：脑图内建目录后就地改名，PATCH /spec-modules/:id 返回 500
  `null value in column "path" violates not-null constraint`，改名失败。
- **根因**：UPDATE 里 `path = $5 || substring(path, $6)`——pg 以 unknown
  类型传参，**substring 的重载解析选了 (text, text) 正则变体**（unknown
  参数优先 text 类别），'起始位置' 被当正则匹配不上 → NULL → 整列 path
  被写成 NULL。该 UPDATE 此前从未被任何调用方执行过（P7-2 只建不
  改），脑图的就地命名是第一个消费者。
- **修法**：显式 `substring(path, $6::int)` 锁定整数重载。
- **验证**：同一请求重放返回 200，物化 path `/冒烟目录/` 正确。
- **状态**：已修复（2026-09-07）。

## ㉔ 目录层不进图 + 添加无入口（⑯ 残余，本轮升级为结构设计）

- **现象**：从「全部用例」进脑图，用户期望看到「全部用例 → 测试（目录）
  → dd（目录）+ 用例」的完整层级（此前 ⑬ 的决策是模块树不进图）；同时
  前置条件、目录、用例、步骤、预期**全都没有图内添加入口**——上一轮只补

- **修法**（结构 + 键位 + 占位槽三件套）：
  ① **目录层进图**：root（全部用例/点中目录）→ 目录子树（spec_modules

  预期；目录节点带目录徽记与子树计数（与左树同口径），默认展开
  （closedDirs 收起集），空目录也可见可点；
  ② **键位按种类落点**：Tab=子级（目录→该目录建用例、用例→步骤、步
  骤→预期），Enter=同级（目录/root→建同级目录、用例→同模块建用例、
  步骤→后续步骤）——「在哪建、建什么」由选中节点的种类唯一决定，键位
  只有两个，徽记即时反馈建出来的是什么；
  ③ **空槽占位节点**：展开的用例没有前置时画「＋ 前置」、没有步骤时画
  「＋ 步骤」虚线占位节点（点击即建、进编辑）——前置此前没有任何图内
  入口，占位槽让「补什么」长在它该在的位置上；只读视角不画；
  ④ **目录的建后命名闭环**：Enter 建目录 → 占位名 → 就地改名输入（改名
  走 updateSpecModule 最小提交；新目录先进 extraModules 覆盖位立即上
  图，不等父表重取）；存量目录的双击改名等 P7-6 完整管理面（改名牵动
  scope path 的场景需要父组件配合换筛）。
- **状态**：已实现（2026-09-07）。

## 第十三轮反馈（㉟㊱，同日——IME 截断 / 改名弹窗不弹）

  弃 `onPressEnter` 改带同一守卫的 `onKeyDown`。画布级 document 键位监听本就跳过
  INPUT 焦点，无需改。

## 第十四轮反馈（㊲㊳，同日深夜复测——IME 残余 / 抽屉细线）

## ㊲ 脑图就地编辑：输入法检测仍有问题（㉟ 残余）

- **现象**：Tab 建节点后就地编辑，中文输入法打字、回车选字**仍**被当成提交——
  组合文本截断、输入框关闭（API 日志侧写：一次标题 PATCH 后 1 秒内即 DELETE，
  该次编辑未按预期落全）。
- **根因**：㉟ 的守卫是 `isComposing || keyCode === 229`，只覆盖「组合进行中」
  的 keydown，两头都有残余——① Safari/WebKit 把**确认候选**的 Enter 排在
  compositionend **之后**派发：此时 `isComposing` 已是 false、`keyCode` 是 13，
  两道检查都兜不住，选字回车直达提交；② 反过来，部分输入法在非组合态也把
  keydown 报成 229，裸 229 检查把用户真正的提交 Enter 一起吞掉（「回车提交
  不了」是同一缺陷的另一半）。
- **修法**：改按**组合事件跟踪**（`useImeGuard`：compositionstart/end 记组合态
  与结束时刻）——组合期一律放行；组合结束后 100ms 窗口内的 Enter/Tab 视作
  选字确认键放行**一次**（只吞一次，紧接的第二击是用户真意图）；裸 229 检查
  撤销，`isComposing` 保留为次级兜底。标签弹窗同款守卫。
- **状态**：已修复（2026-09-07，待复测）。

## ㊳ 列表新建用例：前置条件/步骤输入框「折叠在一起」（㉙ 同症异灶）

- **现象**：列表视图新建用例抽屉里，前置条件与步骤/预期输入框缩成细线、挤作
  一团（㉙ 在脑图里的同形症状，这次在抽屉）。
- **根因**：antd 抽屉关闭后**内容仍挂在 DOM**（`ant-drawer-content-wrapper-hidden`
  = display:none，无 destroyOnClose）。抽屉再次打开换例时，表单回填
  （useLayoutEffect 按 item 换值）发生在面板尚处隐藏态的提交里，
  AutoGrowTextarea 对着 display:none 的框量 `scrollHeight = 0`，高度被写成
  ~2px；面板随后可见，但 `[value]` 不再变，细线高度定格。
- **修法**（两层）：① 抽屉加 `destroyOnHidden`——关闭即卸载内容，每次打开都
  是**可见态的全新挂载**，隐藏态量高从根上不存在；② AutoGrowTextarea 加防御
  ——`offsetWidth === 0`（不在渲染树）时跳过写高、记为待办，ResizeObserver
  报告盒子出现/宽度变化时补量（顺带修掉一个潜在旧病：窗口缩放改变换行数后
  `[value]` 依赖重量不到，高度滞留）。
- **状态**：已修复（2026-09-07，待复测）。

## ㊳b 脑图空目录建首例仍整树重框（㉙ 残余）

- **现象**：空目录里 Tab 建第一条用例，整图重新 fitView、缩放掉下去，刚打开

## 第十五轮反馈（㊴，2026-09-08 上午复测——就地编辑打不了中文）

## ㊴ 脑图就地编辑框无法用输入法输入中文（㉟/㊲ 的真正根因）

- **现象**：Tab 建用例/双击就地编辑后，中文输入法打字——组合反复被拆掉，
  偶尔漏进一个字（库里该用例标题 `dd`、前置 `mmm`、步骤 `99iioj`、预期
  `吗；（！@……&*（）」「｜`，是四次徒手挣扎的痕迹）。英文能勉强留下。
- **根因**：不在键位守卫——㉟/㊲ 的守卫只拦 Enter/Tab，字母键在改前改后
  走的是同一条放行路。真凶是**编辑框的受控 value 走了画布 store 的往返**：
  每个按键 `setEdit(value)` → MindMapCanvas 重渲染 → 新 nodes prop →
  React Flow StoreUpdater 的 **passive useEffect**（晚一拍）→ zustand store →
  节点重渲染 → 输入框才拿到新 value。React 对受控输入有事后校正
  （`finishEventHandler` → `restoreStateIfNeeded`）：事件派发完拿**fiber 上
  还没更新的旧 props** 回写 DOM——普通英文打字下一帧被 store 往返自愈；
  但**组合进行中回写 `input.value` 会直接拆掉输入法会话**，中文永远组不成。
  ㉟ 当初的「组合文本被拦腰截断」其实已是这一机制（Enter 只是叠加因素），
  两轮键位修复都没碰到它。
- **修法**：编辑草稿改为 `MindEditInput` 的**组件本地态**（useState(seed)，
  按键回显与 onChange 同一次提交完成，无 store 往返、无事后回写）；`edit`
  状态只记 `{nodeId}`，`onCommit(value)` 提交时把终值交给 `commitEdit`。
  顺带消掉每按键一次的 nodes 换代（store adopt churn）。IME 键位守卫（㊲）
  原样保留在该输入框内。
- **取证**：API 日志侧写（同一用例 09:58–09:59 四连 PATCH）+ 该用例落库的
  键盘乱敲残迹 + react-dom 源码 `createAndAccumulateChangeEvent →
  enqueueStateRestore → restoreStateIfNeeded` 的受控回写路径。
- **状态**：已修复（2026-09-08，待复测）。
