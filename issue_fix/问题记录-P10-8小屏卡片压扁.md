# P10-8 卡片模型未兼容小屏：列表被压扁、操作区被裁掉

> 2026-09-21 用户实测报告：P10-8 做「上下两张卡 + 卡内滚动」时没有兼容小屏幕——
> ① 小屏时列表内容挤在一起、看不到操作按钮；② 小屏时内容卡片变小、实际展示的内容
> 严重缩小。

## 现象

- 窄屏或矮视口（手机竖屏 / 手机横屏 / 桌面矮窗口）打开任一 `content-split` 列表页
  （接口列表、流程列表、执行记录、成员、Mock、用例库、仓库各页、工作台等）：
  工具卡下方的列表卡只剩很矮的一条，表格内容挤在一起，行内操作（编辑 / 删除等）
  与末行筛选、操作按钮都够不着。
- 全局层（数据看板 / 项目管理 / 系统管理 / 个人中心）的 `.page-card` 同款：正文被压没，
  工具卡的下缘被卡片自己的 `overflow: hidden` 裁掉。

## 根因

卡片模型的前提是「高度充裕」，而 P10-8 当时没有为「装不下」留兜底（计划 14.6 把
≤560px 降级形态记为残留小尾，只落了卡片内距收紧）：

- `.content-split { display: flex; flex-direction: column; overflow: hidden }`：容器高度由壳
  给定（`.console` 100dvh + `.frame` 的 flex 行），`overflow: hidden` 使它不再是滚动容器；
- `.content-split > .page-toolbar { flex: 0 0 auto }`：工具卡按内容高度、不参与收缩；
- `.list-card { flex: 1 1 auto; min-height: 0 }`：下卡吃剩余高度，**允许被压到 0**。

窄屏下工具卡（标题 + 操作 + 筛选）换行堆叠、高度轻松 300px 起步；≤940px 顶栏模式又让
侧栏变成会换行的横条、自身再吃掉一百来像素。剩余高度被吃光后：

1. `.list-card` 被压成 0～几十像素——列表只剩一条缝，卡内滚动几乎不可用，行内操作与
   表尾内容都要在这条缝里找，读起来就是「内容挤在一起 / 严重缩小」；
2. 工具卡不收缩，当「工具卡 + 剩余高度」超出容器时，超出部分被 `.content-split` 的
   `overflow: hidden` 从下缘裁掉——末尾的筛选 / 操作按钮直接消失。

同根因另一处：全局层 `.console[data-topnav] .page-card { height: 100%; overflow: hidden }`
+ `.page-card-body { flex: 1 1 auto; min-height: 0 }`——正文同样可被压成 0，工具卡下缘
被卡裁掉。

## 修法

全部在 `apitest-web/src/design-system.css`（纯 CSS，未动取数、分页、markup）：

1. **装不下就由容器滚，不再压扁下卡**：`.content-split` 的 `overflow: hidden` 改为
   `overflow-x: hidden; overflow-y: auto`。`.content-split` 与 `.content` 是同一元素，
   滚动因此仍落在规则 5 的「唯一滚动容器」上；高度够时无溢出、无滚动条，桌面形态不变。
2. **下卡保底**：`.list-card` 的 `min-height: 0` → `min-height: 240px`。剩余高度不够时
   不再被 flex 压成一条缝，差额交给第 1 条滚动兜底；列表总有一屏可读高度，卡内滚动与
   吸附表头照常成立。
3. **≤560px 紧凑档（首版曾写成「退回整页滚动」，按用户定案改为保留卡片模型）**：
   卡片模型在手机上保留（工具卡常驻、列表卡吃到视口底），改为把「壳 + 工具卡」收一档
   腾高度——`.page-head` 标题与操作合并一行（原先纵向堆叠要 100px 上下）、描述收成一行
   截断、标题 19→17px / 描述 13→12px、`.content` 内距 `--s5/--s8` → `--s3`、
   `.content-split > .page-toolbar` 与 `.console[data-topnav] .page-card-toolbar` 内距收到
   `--s3/--s4`、工具卡内标题行与筛选行的间距 20→12px。**表格正文 13px / 表头 11px /
   mono 机器数据不动**（列表可读性底线）。
4. **极端矮视口兜底**：`@media (max-height: 460px)`（横屏手机、桌面矮窗口）下才退回规则 5
   的原始形态——两卡按内容高度自然排布、`.content` 整页滚动、吸附表头 `position: static`；
   全局层同款（`.page-card { height: auto }` + `.content { overflow-y: auto }`）。
5. 全局层同源兜底：`.console[data-topnav] .page-card { overflow-y: auto }`
   + `.page-card-body { min-height: 240px }`——装得下时卡内滚动照旧，装不下时整卡滚动。

**未做**（用户已提，待逐页定候选列）：窄屏表格的列显隐/截断（`≤560px` 隐藏创建人/更新人
等次要列，关键列 truncate）；`filter-bar` 限高。

## 第二轮（2026-09-21 稍晚，按用户截图复核后修正方向）

**复核证据**：用户截图（2000×980 @2x ≈ **1000×490 的视口**，侧栏仍是纵向 ⇒ 宽度 > 940px）。
截图里接口列表只看得见 `路径 / 用例数 / 耗时 / 状态 / 创建人 / 更新人`，**名称列不可见、
行内操作按钮完全看不到**，路径与邮箱普遍被 `…` 截断。⇒ 前两轮把「小屏」当成窄屏（≤560px）
是**判错了方向**：用户的场景是**窄/矮窗口**（1000×490），而当时的两档（≤560px 宽、≤460px 高）
都不命中，所以他看不到任何变化。

**真正的根因（横向为主）**：
1. 接口表列预算超卡片宽：固定列宽合计 = 选择 42 + 用例数 76 + 耗时 82 + 状态 92 +
   创建人 148 + 更新人 148 + 操作 166 = 754px，再加路径 `28%` 与名称列 ⇒ 约 1100px，
   而 1000px 窗口里卡片只有 ~950px ⇒ 名称列被挤到最小、`操作` 列被推出卡片右缘
   （要横滑才能点到）——即「看不到操作按钮 / 内容严重缩小」。
2. 高度上，490px 的视口里 `--s5/--s6/--s8` 那套壳层内距与 21px 标题偏奢侈，工具卡吃掉
   的高度没能让给列表卡。

**修法（补充，仍在 `design-system.css`）**：
1. **行操作列常驻右侧**：`.grid .col-actions { position: sticky; right: 0; background: var(--surface) }`
   ——超宽表横向溢出时操作列钉在滚动容器右缘，不用先横滑再点；行 hover / 选中态的底色
   同款跟随（sticky 单元格必须不透明，否则滚过的内容会透上来），`thead th.col-actions`
   抬到 `z-index: 2` 压在吸附表头之上。
2. **≤1100px 收次要列**：`.col-owner { display: none }`（创建人/更新人两列共 296px，
   详情与审计日志里都能查）⇒ 1000px 窗口里名称列拿回 ~300px，操作列回到卡内；
   同档给常驻操作列补一道 `inset 1px` 分隔线（折叠边框在 sticky 单元格上会丢线）。
3. **紧凑档改为「宽度或高度」触发**：`@media (max-width: 560px), (max-height: 620px)`
   ——矮而宽的窗口（1000×490、半屏窗口）同样收壳层内距、标题 17px、描述一行截断、
   工具卡内距 `--s3/--s4`（这一档与宽度无关的规则单独成块；`readouts` 两列、登录卡等
   窄屏专属降级仍只在 ≤560px）。整页滚动兜底仍只在 `max-height: 460px`。

## 第三轮（2026-09-21 晚，1273×590 复测反馈）

**现象**：第二轮修完后用户在 **1273×590** 左右的窗口（评审小窗）复测，列表内容
仍展示不完全、且混乱（名称列被挤没、邮箱/路径大量 `…` 截断）。

**根因**：两轮修复的断点都以「视口尺寸」为准，1273×590 正好落在缝隙里：

- 高度 590 命中紧凑档（≤620px）——纵向收紧已生效；
- 宽度 1273 **不命中**收列档（≤1100px），但展开侧栏（210px）+ `.content` 内距
  （48px）后，卡片实际只有 **~1015px**；接口表固定列（选择/用例数/耗时/状态/
  2×148px owner/操作 ≈ 820px）+ 路径 28% ≈ **1100px** ⇒ 名称列被挤到几十像素。
  断点量错了对象：约束是「表格容器宽」，不是「视口宽」。侧栏收起成 rail（56px）
  时容器 ~1169px 又确实放得下——同一视口下两种侧栏形态需要不同结果，视口断点
  天生给不了。

**修法（纯 CSS，`apitest-web/src/design-system.css`）**：

1. **列预算断点改容器查询**：`.table-scroll` 挂 `container-type: inline-size;
   container-name: grid`，原 `@media (max-width: 1100px)` 收 owner 列的块改为
   `@container grid (max-width: 1100px)`。按表格容器实际宽生效：1273 视口展开
   侧栏 → 容器 1015 命中收列；收起 rail → 1169 不命中照常显示；全局层无侧栏
   （1225）不命中。覆盖所有在 `.table-scroll` 里的表格（含 modal 内的表）。
   行操作列常驻 sticky 的规则不变。
2. **`flow-list-wrap` 的 min/max 矛盾**：`min-height: 420px` 在 CSS 里压过
   `max-height: calc(100dvh - 300px)`（590 视口下 max 只有 290），规则失效、
   列表框比视口还高。min 降为 240px（与列表卡保底同口径；正常桌面无行为差异）。
3. **`import-tree`（用例导入弹窗的树）**：`max-height: calc(100dvh - 420px)` 在
   590 视口下只剩 170px。加 clamp 下限：`clamp(200px, calc(100dvh - 420px), 60dvh)`，
   正常桌面不变。

**受益页面**（owner 列在容器 ≤1100px 时收起，全部在 `.table-scroll` 内）：
接口列表、流程列表、场景列表、环境、数据源、用例库、告警、资源日程、公共脚本、
Mock、执行记录；其余列表页（成员、CI 任务、审计日志、仓库各页等）列少不溢出，
靠行操作列 sticky + 表内横向滚动兜底。

**未做（沿用上轮遗留）**：窄屏表格的列显隐/截断（≤560px 隐藏次要列）逐页定候选列；
`filter-bar` 限高；`workbench` 两栏断点（2862 行的 `@media (max-width: 1100px)`，
按视口算在 1273+侧栏下同样漏判，但主栏 ~699px 尚可用，暂不动）。

**状态**：已修（2026-09-21，纯 CSS，零迁移）。**未经浏览器验证**，按仓库约定留给用户
目视验收。建议重点看：1273×590 展开侧栏（接口列表应能看到名称列全名 + 行内操作）、
1273×590 收起 rail（owner 列应回来）、正常 1440+ 桌面（形态与之前一致）、流程编辑器
列表模式（矮窗口下框高 ~290px 不再撑破）。

## 第四轮（2026-09-22 用户取舍：卡片永远吃满高度 + 去掉按高度的回退）

**诉求**：默认情况下内部可滚动的列表卡底缘要**与侧边栏齐平**（永远吃满剩余高度），不要再
按视口高度降级；用例库（`SpecCases`）翻页条页面一变矮就看不到，要**常驻卡底**。

**改动（纯 CSS，`apitest-web/src/design-system.css`）**：

1. **移除 `@media (max-height: 460px)` 极端矮视口兜底**：原块把 `.content-split` 改 `display: block`、
   `.list-card` 改 `display: block; min-height: 0`、吸附表头改 `static`、全局层 `page-card` 回 `height: auto`，
   即在矮窗口退回整页滚动。删除后任何视口高度都保持卡片模型 —— 列表卡永远 `flex: 1 1 auto` 吃满
   高度、底缘与侧栏齐平。（代价：极矮视口回到「页面滚 + 卡内滚」两层，按用户取舍接受。）
2. **紧凑档去掉 `(max-height: 620px)` 那半**：`@media (max-width: 560px), (max-height: 620px)` 改为
   `@media (max-width: 560px)`——只按宽度收「壳 + 工具卡」，不再按高度触发。
3. **用例库翻页条常驻卡底**：`.spec-main .pager { position: sticky; bottom: 0; background: var(--surface);
   border-top: 1px solid var(--line); padding: var(--s3) 0; margin-top: 0; }`——pager 是 `.spec-main`
   （卡内右栏纵向滚动容器）的直接子节点，钉在其底缘，滚表时不再滑出视口；页面滚动仍只落在
   `.spec-main`（规则 5 不破）。

**状态**：已改（纯 CSS，零迁移）。**未经浏览器验证**，留给用户目视验收：默认桌面卡底与侧栏
齐平；矮窗口不再整页滚动而是卡内滚；用例库长列表翻页条始终贴卡底可见。

## 状态

已修（2026-09-21 三轮，纯 CSS）。**未经浏览器验证**：按仓库约定（`.kilo` 的 Validation Ownership）
断点目视验收留给用户——建议至少看这三档：**1000×490 窄矮窗口**（本轮主场景：接口列表应
能同时看到名称列与行内操作按钮、不用横滑）、≤560px 手机宽度（工具卡合并一行、列表卡吃到
视口底）、常规桌面宽度（形态应与改造前一致：>1100px 不隐藏创建人/更新人）。
