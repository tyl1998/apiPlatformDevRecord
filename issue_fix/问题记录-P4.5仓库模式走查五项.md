# P4.5 仓库模式走查五项（导航归属 / 命名 / 解绑 / 吊销列表 / 在途状态）

## 现象

用户走查仓库模式反馈（除产物链路外的五项）：

1. 执行完仓库任务进入执行详情页（`/projects/:id/pipeline-runs/:runId`），侧边栏高亮的
   是**接口管理**；
2. 父执行记录里，仓库任务的类型标签叫「CI 执行」；
3. 凭据页点「解绑」后界面没有任何可感知的变化；
4. 仓库任务开启「注入 SDK 上报变量」后，每跑一次就多一行 `ci 纯测试 #N` 的 token、
   run 结束又被吊销，已吊销的把列表越堆越长；
5. 任务列表页看不出哪些任务正在执行或排队，要逐个展开行内历史才知道。

## 根因

1. `ProjectShell` 的导航归属只认 `segments[2] ∈ PAGES`，`pipeline-runs` 不在其中，回落
   到兜底值 `endpoints`——「从执行详情页回来侧边栏亮着接口管理」就是兜底选错的。
2. `reports.kindRunner` 的文案沿用了实现视角的「CI 执行」（kind=runner）。用户定名：
   对用户它就是「仓库」；触发来源（手动/定时/Webhook）以后由触发人一列区分，等用户
   管理阶段再补。
3. 解绑只是把 `repositories.status` 置 `unbound`（历史保留，边界 18），但
   `GET /repository` 仍把这行返回，凭据页的连通状态面板除了状态词什么都照旧——地址、
   用例数、跟踪分支、解绑按钮全在，界面上等于没解绑。
4. **按 run 现签 token 是既定设计**（`jobSpec.ts`：库里只存 scrypt 哈希，明文取不回来，
   「注入」只能在凭据只出现一次的地方新签一张；run 终态由 `complete` 顺手吊销，防行数
   无界增长）——这一半不改。缺陷在列表：`GET /ingest-tokens` 不过滤 `revoked_at`，
   吊销的（CI 签的 + 手工吊销的）全部照列。
5. 任务列表没有任何在途信息：状态只在展开后的行内历史里，而列表本身既不返回也不轮询
   每个 run 的状态。

## 修法

1. `ProjectShell.tsx`：新增 `SECTION_ALIASES`（`{ "pipeline-runs": "repo" }`），未知段
   先查别名再兜底 `endpoints`——执行详情页侧边栏高亮「仓库模式」。
2. `i18n.ts`：`reports.kindRunner` 「CI 执行」→「仓库」/ "CI run"→"Repository"
   （类型筛选下拉同步换）；`pipelineRun.title`「CI 执行」→「仓库执行」/
   "CI run"→"Repository run"（执行详情页标题与页签）。
3. `repositories.ts`：`GET /repository` 加 `AND status = 'active'`——解绑后回 `null`，
   凭据页落到「还没有绑定仓库」空态（文案「第一次上报时自动绑定」对解绑后同样成立），
   解绑有了可见的结果。历史不丢：用例树与上报记录两页不依赖这一行；下一次上报带新
   地址重新激活（`bindRepository` 原逻辑）。
4. `repositories.ts`：`GET /ingest-tokens` 加 `AND revoked_at IS NULL`——吊销即从管理
   视图消失（行留在表里供「那次上报是谁报的」对账）。列表只剩生效中的 token：手工建
   的几张 + 在途 run 现签的那张。
5. 在途状态走数据而不是交互：
   - `routes/ciTasks.ts` 列表 SQL 追加 `LEFT JOIN LATERAL`（聚合形状：无在途时恒一行、
     count=0 身份列 NULL），随行带出 `activeRun`（最新在途 run 的 id/#N/状态）与
     `activeRunCount`；`mapCiTask` / 前后端 `CiTask` 类型补这两个可选字段（仅列表填充）。
   - `CiTaskList.tsx`：任务名列内展示 `RunStatusTag`（排队中/执行中）+ 可点的 `#N`
     （`cell-link`，点击直达 run 详情，`stopPropagation` 不触发行的编辑跳转；并行多条时
     hover 提示总数）；列表按 10s 静默轮询（与 Runner 池同一节奏，不闪 loading），
     终态后提示自然消失。
