# P8-6 统计页接线两缺陷（按接口/按套件榜 500、overview 带 projectIds 必炸）

> 2026-09-10，P8-6 验收第一轮（用户反馈「按用例、按接口统计数据失败」）。
> 定性依据：`.dev-logs/api.log`——`topN=endpoint`/`topN=suite` 与全部
> `stats/overview?…&projectIds=…` 请求 500；`topN=case` 实际是 200（用户看到的
> 失败文案来自同页 overview / endpoint 维的两条 500，不是用例维本身）。

## 缺陷① `function max(uuid) does not exist`（P8-6 带入）

**现象**：数据统计页失败 TopN 切「按接口」「按套件」→ 该段 500（统计数据加载失败）。

**根因**：P8-6 给 TopN 榜补下钻 refId 时写了 `MAX(e.endpoint_id)` /
`MIN(ei.target_id)`——**Postgres 没有uuid 类型的 min/max 聚合**（SQLSTATE
42883，hint 提示需要显式类型转换）。ci_task 维直接 `t.id` 进 GROUP BY、case 维
本来就带 case_id，所以只有这两维炸。tsc 抓不到（SQL 字符串），P8-4 自己的教训
「先在 psql 里过一遍再落码」没有执行。

**修法**：`(ARRAY_AGG(x ORDER BY created_at DESC) FILTER (WHERE x IS NOT NULL))[1]`
——ARRAY_AGG 对任意类型可用；语义顺带更对：取「组内**最近一次**失败的引用」
（同名接口快照漂移时指向最新那次，而不是任取其一）。

**状态**：已修（stats.ts topSql endpoint/suite 两维）；修复后的 SQL 已在 dev 库
psql 实跑验证（endpoint 维 / suite 维各一条，ref_id 正常返回）。

## 缺陷② assets / coverage 的 scope 拼接双 WHERE（P8-4 潜伏，P8-6 接线触发）

**现象**：`GET /stats/overview?…&projectIds=<pid>` 一律 500（`syntax error at or
near "WHERE"`，position 618）——项目页 Readout 行整段「统计数据加载失败」；
数据看板同炸。`stats/coverage` 的 specRows / automatedRows 同款（前端尚未接线，
未暴露）。

**根因**：P8-4 的 assets 查询在带后续 `WHERE status…` 的子查询里用了 `scopeWhere`
（片段自带 ` WHERE project_id = ANY($n)`）：

```sql
(SELECT COUNT(*)::int FROM spec_cases${scopeWhere(idx)} WHERE status <> 'deprecated')
-- scope 全量时片段为空 → 合法；带 projectIds → "FROM spec_cases WHERE … WHERE …" 双 WHERE
```

**为什么 P8-4 没发现**：验收/EXPLAIN 用的是系统管理员不带 projectIds
（`scope.all` → `scopeWhere` 返回空串 → 语法成立）。P8-6 前端把项目层统计页接
到 `/stats/*` 且**永远带 projectIds**（非管理员看板也被 `user_project_roles` 兜
成显式集），潜伏缺陷当场全部触发——「前端接线暴露后端潜伏缺陷」的标准案例。

**修法**：受影响的六个子查询统一改为 `scopeAnd`（` AND project_id = ANY($n)`）
拼进既有 WHERE 之后：

- overview assets：`spec_total` / `spec_reviewed` / `spec_automated` /
  `repo_case_total` 四处（其余五个无后续 WHERE 的子查询改写为
  `WHERE TRUE${scopeAnd}` 保持同构）；
- coverage：`specRows`（`WHERE status = 'reviewed'${scopeAnd}`）与
  `automatedRows`（scopeAnd 以 `sc.project_id` 列并入 JOIN 后的 WHERE）。

排查过 stats.ts 全部 `scopeWhere` 残留调用点（endpoints/test_cases 裸子查询、
projects 路由三处 GROUP BY 子查询、coverage 的 endpoints/firstCase）——均无后续
WHERE，合法。

**状态**：已修；spec_total / spec_automated 的带 projectIds 形状已在 dev 库 psql
实跑验证（197 / 2，正常返回）。教训回写进 stats.ts 注释：scope 片段一律
`scopeAnd`，除非子查询确无其他条件。
