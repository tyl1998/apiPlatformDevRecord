# 仓库执行详情页面包屑断头（2026-09-02 验收反馈第 1 项）

## 现象

仓库模式（任务列表 / 行内展开历史）进入某条历史执行记录
（`/projects/:pid/pipeline-runs/:runId`）后：

- 顶部面包屑仍显示「{项目名} / 仓库模式」，其中「仓库模式」是不可点的纯文本；
- 侧边栏「仓库模式」高亮正常（能看出来自己还在仓库分组里），但没有任何可点的
  返回入口回到仓库模式首页（任务列表）——只能靠浏览器回退。

## 根因

`ProjectShell.tsx` 的 detail 页判定只认五种「路径带 id 的子页」：
endpoints / flows / suites / data-sources / suite-reports。
`pipeline-runs/:runId` 是**独立路由**（P4.5-11 落地时不在 `repo/*` 之下，靠
`SECTION_ALIASES` 把侧边栏点亮归组到 repo），没进这份判定：

- `detailOpen = false` → 面包屑走「非 detail」分支，「仓库模式」渲染成 `<strong>`
  而不是可点的 `crumb-link`；
- 于是「进入子页后中间那段变成回链」的既有机制恰好在这个页面上失效——不是缺
  返回按钮的设计，是一个漏加的成员。

## 修法

`ProjectShell.tsx`：

- `pipelineRunOpen = routeSegment === "pipeline-runs" && Boolean(segments[3])` 进
  detail 判定（`detailOpen` 并集）；
- 面包屑 detail 分支为 pipeline run 渲染 `detailTitle ?? t("pipelineRun.title")`，
  中间段「仓库模式」回链指向 `/projects/:pid/repo`（任务列表索引路由——`active`
  经别名归组就是 repo，回链目标天然正确）；
- `PipelineRunPage.tsx` 经 outlet context（`setDetailTitle`）把 `#序号` 上推给
  面包屑，与套件报告详情页「{项目}/报告列表/{报告名}」同一模式。
