## 一、首轮验收反馈（4.0.2.1）

### 1. 提取失败无法定位

**问题**: 提取失败只报合并消息 `could not extract: a, b`，无法区分路径写错、响应不是 JSON、字段真是 null 三种完全不同原因。

**根因**: `applyExtracts` 只返回 `missing: string[]`，没有逐条原因。

**修复**:
- 后端: 新增 `013_p12_extract_results.sql`，`executions.extract_results` 逐条记录 `{ name, from, path, ok, value | reason }`
- 后端: `applyExtracts` 返回 `results: FlowExtractResult[]`，区分「路径不存在」与「字段确实是 null」，body 解析失败也独立报出
- 前端: 提取行下方逐条显示 `= 值` 或具体原因，快照抽屉与执行记录页同样可见
- `executeRequest` 提取读**未掩码**响应体；掩码后再提取会把等于 secret 的 token 变成星号

**涉及文件**: `migrations/013_p12_extract_results.sql`, `lib/flow.ts`, `lib/run.ts`, `lib/flowRun.ts`, `models/types.ts`, `components/ExecutionSnapshot.tsx`, `components/FlowNodeDrawer.tsx`

### 2. 节点只显示单步调试结果

**问题**: 执行完整流程后打开节点，仍显示旧的单步调试结果。

**根因**: 节点运行结果只来自 `setResult(runs[0])` 的步骤执行查询，但流程运行完并没有更新步骤的最新执行。

**修复**:
- 后端: 新增 `GET /flows/:flowId/nodes/executions?nodeId=`，返回该节点的流程步骤与单步调试**混合**历史（新→旧）
- 前端: 抽屉取 `runs[0]`，面板标注「来自流程运行 / 来自单步调试」

**涉及文件**: `routes/flows.ts`, `components/FlowNodeDrawer.tsx`

### 3. 画布上不能删节点

**问题**: 删除节点需要先点开抽屉，在抽屉内删除。

**修复**:
- 节点悬停显示删除按钮（`nodrag` 避免被画布拖拽吞掉）
- Backspace/Delete 删除选中节点与连线
- `onNodesDelete` 回写文档（画布只持有位置，不回写的话下次重建节点复活）

**涉及文件**: `components/FlowWorkspace.tsx`, `design-system.css`

### 4. 节点不能引用用例

**问题**: 节点只能从接口种入。

**修复**:
- 后端: 新增 `GET /flows/node-source?endpointId=|caseId=`，用例来源**连同断言一起带过来**
- 前端: 节点来源可选「接口」或「用例」，用例来源带入断言
- 仍是快照复制，来源后续被改不回溯

**涉及文件**: `routes/flows.ts`, `api.ts`, `components/FlowNodeDrawer.tsx`

### 5. 提取不能快速选取

**问题**: 提取只能手写 JSONPath/header 名。

**修复**:
- 复用 `JsonPathPicker` / `HeaderPicker`，从**本节点最近一次响应**勾选路径生成提取
- 变量名按末段自动建议（`$.data.access_token` → `access_token`）
- 没跑过的节点禁用并给出原因

**涉及文件**: `components/FlowNodeDrawer.tsx`

### 6. 变量引用容易记错

**问题**: 没有机制帮助用户记住哪些变量可用。

**修复**:
- 新增 `VariablePicker` + `lib/flowVariables.ts`
- 按**上游步骤提取 → 流程变量 → 环境变量 → 内置动态变量**分组
- 上游只列**真正在它之前执行**的节点（沿边反向求祖先）
- 流程初始变量处整组隐藏步骤提取
- 环境 secret 只列名不列值

**涉及文件**: `components/VariablePicker.tsx`, `lib/flowVariables.ts`, `components/FlowNodeDrawer.tsx`, `components/FlowWorkspace.tsx`, `i18n.ts`

### 顺带修正

- 节点 id 从 `Date.now()` 派生改为 `crypto.randomUUID()`，防止同毫秒创建或复制流程撞 id
- `METHODS`/`BODY_TYPES` 抽到 `lib/http.ts`，避免 `run.ts` ⇄ `flow.ts` 循环依赖

**涉及文件**: `lib/http.ts`, `lib/run.ts`, `lib/flow.ts`, `components/FlowWorkspace.tsx`

## 二、二轮体验修复（4.0.2.2）

### 7. 脚本工具栏按钮重叠

**问题**: 自定义断言脚本的展开、来源选择、存为公共/脱离、试运行、删除按钮挤在同一行，删除与试运行重叠。

**根因**: `AssertionEditor` 的 `.assertion-row` 使用固定 grid 轨道，控制数量超出轨道后换行错乱。

**修复**:
- 统一为「左侧来源 / 右侧动作」两区布局
- 删除按钮独占右端，窄屏时动作组整体换行不拆散
- 前置脚本 `.hook-head` 同款两区布局 + 补齐 CSS

**涉及文件**: `components/AssertionEditor.tsx`, `design-system.css`

### 8. 输入 `{{` 时画布步骤消失

**问题**: 在节点抽屉中输入 `{{ss` 时，画布上整体步骤短暂消失。

**根因**: 抽屉每次输入都触发 `setNodes(steps.map(...))` 全量重建 React Flow 节点。React Flow 在重建中间态收到的空节点集导致画布闪白。

**修复**:
- 画布只投影节点卡片真正展示的字段（名称/Method/URL/提取计数/断言计数）
- 请求 body、headers、variables 等抽屉编辑细节不再每次按键就 `setNodes`
- 同步降为 `startTransition`

**涉及文件**: `components/FlowWorkspace.tsx`

### 9. 用例来源关闭后丢失

**问题**: 从用例种入节点后关闭抽屉，重新打开来源选择器是空的。

**根因**: 节点没有保存来源信息，`sourceKind` 初始化为 `"endpoint"`。

**修复**:
- 节点新增 `sourceCaseId/sourceCaseName` 作为**显示来源**（请求仍是完整快照）
- 重新打开时 `sourceKind` 根据 `sourceCaseId` 判断
- 用例删除后仍显示快照名称而非空白

**涉及文件**: `models/types.ts`, `lib/flow.ts`, `routes/flows.ts`, `api.ts`, `components/FlowNodeDrawer.tsx`

### 10. Query/Path/Header 没有变量补全

**问题**: URL 和 Body 有 `{{` 补全，但 Query/Path/Header 的值列是裸 input。

**修复**:
- `KeyValueEditor` 接受 `variableOptions` 参数
- 有选项时 value 列和文本模式都替换为 `VariableField`
- 接口编辑页的 KeyValueEditor 同步接入

**涉及文件**: `components/KeyValueEditor.tsx`, `components/FlowNodeDrawer.tsx`, `components/EndpointWorkspace.tsx`

### 11. 前置试运行黑屏

**问题**: 点击前置试运行后页面崩溃白屏。

**根因**:
- 后端 `/scripts/try` hook 分支返回 sandbox 原始结果，缺少 `name/type/changed`
- 前端 `PreRequestHookEditor` 将 `ScriptTryResult | HookResult` 强转为 `HookResult`
- `HookOutcome` 读 `outcome.changed.length` 时 `changed` 为 undefined → 整页崩溃

**修复**:
- 后端: hook try-run 标准化返回完整 `HookResult`（含 `changed` 计算）
- 前端: 删除不安全强转，使用 runtime guard (`isHookResult` + `normalizeHookResult`)

**涉及文件**: `routes/scripts.ts`, `components/PreRequestHookEditor.tsx`, `lib/hookResult.ts`

## 三、三轮体验修复（4.0.2.3）

### 12. URL 输入框过短

**问题**: 接口管理和流程管理的 URL 输入框只显示约 20 字符。

**根因**: 二轮引入 `VariableField` 后的回归。原来的 CSS `.request-url { flex: 1 }` 作用在 input 上，但补全组件把 input 包进了 `span.var-field`。真正的 flex 子项变成这个 span，按 input 固有宽度收缩。

**修复**: `span.var-field` 在 `.request-line` 内设置 `flex: 1 1 240px`，窄屏时整行换行。

**涉及文件**: `design-system.css`

### 13. 用例校验的脚本工具栏删除按钮重叠

**问题**: 测试用例校验内的自定义脚本按钮与删除按钮重叠。接口工作台中栏远窄于流程抽屉，散排的 flex 按钮在窄容器里换行错乱。

**根因**: 第 7 项修复只把删除推到了 `.assertion-script-row > .btn:last-child`，但 verdict 和 collapse 等其他按钮仍在散排，窄容器下挤在一起。

**修复**:
- 重构为与 `.hook-head` 相同的两区结构
- 左侧：折叠、类型、来源、判定
- 右侧：动作组（脱离/存公共、试运行、删除）整组右对齐，560px 以下整组换行

**涉及文件**: `components/AssertionEditor.tsx`, `design-system.css`

### 14. 前置脚本保存后重开消失

**问题**: 前置脚本页面保存后刷新，重新打开步骤脚本消失。

**根因**: 保存时 `persistFlowScripts` 把私有正文转存为匿名 `scripts` 行、节点里只剩 `{scriptId}`，但 `PreRequestHookEditor` 把「有 scriptId」误判为「跟随公共脚本」——公共列表里查不到，正文为空。

**修复**:
- 对齐 `ScriptAssertionEditor` 的既有模式：按 id 回取脚本，**用 name 是否存在**区分公共/匿名
- 匿名脚本显示为「私有脚本」且可编辑（编辑保留 scriptId，更新同一行）
- 回取未完成时编辑器显示加载态而非空白
- 每个 id 只回取一次

**涉及文件**: `components/PreRequestHookEditor.tsx`

## 四、四轮修复（4.0.2.4）

### 15. 前置脚本永久「加载中」

**问题**: 第 14 项修复后，保存前置脚本 → 刷新 → 重开，一直显示加载中。

**根因**: 回取逻辑本身正确（`GET /scripts/:id` 实测返回正文），但结果被 effect cleanup 丢弃：
1. 回取 effect 用了 per-effect `let stale` 守卫
2. React 在**每次 effect 重跑前**都执行 cleanup，不只是卸载时
3. 公共 hook 列表 fetch 落地 → 重渲染 → cleanup 将把在途的回取标为 `stale` → 结果被丢弃
4. `requested` 集合已记下该 id → 重试永不发生
5. effect 依赖整个 `hooks` 数组（每次渲染都是新引用）→ 重跑异常频繁，放大竞态

**修复**:
- 取消只在**卸载**时生效（`unmounted` ref）
- effect 依赖从 `hooks` 数组改为引用 id 的**值**（`referencedIds` 字符串）
- 新增 `unresolvable` 记录回取为空的 id（脚本在流程保存后被删），落到可编辑的空正文并提示
- `resolved`/`unresolvable`/`requested` 三个缓存在切换项目时清空

**涉及文件**: `components/PreRequestHookEditor.tsx`, `i18n.ts`
