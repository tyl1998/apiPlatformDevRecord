## 一、缺陷统计

P2-6 从设计到验收共发现并处理 **21 个缺陷**，其中 2 个造成数据丢失（标注 ⚠️）。按性质分组如下。

### A. 并发模型（6 个）——本切片风险最高的一处

| # | 缺陷 | 现象 | 根因 | 修法 | 状态 |
| --- | --- | --- | --- | --- | --- |
| 1 | 容器节点占令牌，内层图饿死 | 多个并列 loop 容器占满额度后，各自的循环体永远等不到令牌，整条流程挂死到超时 | 准入循环对**所有** ready 节点无差别取令牌，代码与「容器不取」的注释相反 | 准入处按 `isContainerNode` 跳过取令牌 | 已修复 |
| 2 | `setCapacity` 全局踩踏 + 容量泄漏 | 两个并发循环重叠时保存/还原错位，循环结束后池子永久停在高容量；降容量重复扣掉在飞令牌 | 循环并发通过临时抬高**全局**池容量实现 | 改为循环自己的局部信号量 `Semaphore`，删掉 `setCapacity` | 已修复 |
| 3 | ⚠️ 并发请求的令牌记账是假的 | 「循环并发 2 × 请求并发 10」有 20 个请求在飞而池子只记 2 个——文档承诺的「真实并发受预算封顶」不成立 | 令牌按「节点」计数，扇出的 N 个子请求不各占令牌 | 并发请求节点自身不取令牌，**每个在飞的子请求各取一个** | 已修复 |
| 4 | `onProgress` 被内层图共用 | 外层已过 4 步，内层图跑起来把父级计数刷成 1/0/0，前端进度乱跳 | `ctx` 原样传进嵌套 `runGraph`，内层用自己的局部计数回调 | `nested(ctx)` 进入内层图时摘掉 `onProgress` | 已修复 |
| 5 | 并发请求永远停在「执行中」 | 节点一直 running 直到流程超时 | 扇出 worker 的 `for(;;)` 漏了「领到的下标 ≥ 并发数就收工」 | 补 `index >= concurrency` 边界 | 已修复 |
| 6 | 并发单步调试忽略 `concurrency` | 设了并发 5 也只发 1 个请求 | `/nodes/execute` 请求分支走 `enqueueRun`，不看并发字段 | 并发 > 1 改走容器路径（`runGraph` 写容器行 + N 子行） | 已修复 |

### B. 脚本归属与持久化（3 个）——造成数据丢失的一组

| # | 缺陷 | 现象 | 根因 | 修法 | 状态 |
| --- | --- | --- | --- | --- | --- |
| 7 | ⚠️ 保存流程会删掉该流程的内联脚本 | 一次保存后节点上的断言/钩子/后置脚本全没了，再保存报 `referenced script does not exist` | `persistFlowScripts` 对循环体递归调用自己，内层 `collectGarbage` 拿着只含体内 id 的 `seen` 把顶层脚本当垃圾删了 | 遍历与清理分离：内部 `walk` 累加同一份 `seen`，`collectGarbage` 只在外层执行一次；清理清单再取 `seen` 与「最终节点树里实际引用的 id」的并集（`scriptIdsIn`） | 已修复 |
| 8 | 单步调试漏脚本内联 | `pre-request hook "ss" failed: hook script content is missing` | `executeGenericStep` 只调 `prepareFlowNodes`，钩子/断言正文的内联在 `inlineFlowNodeScripts` 里 | 先统一 `inlineFlowNodeScripts` 再 `prepareFlowNodes`，删掉各分支零散内联 | 已修复 |
| 9 | 用例导入流程后保存报「是否公共脚本」 | 导入用例的节点保存报 `referenced script belongs to another case` | 用例的匿名脚本归用例所有，跨宿主跟随会被拒；导入时没做 follow/copy | 导入端 `adoptScriptRef`（公共跟随、匿名复制正文+依赖）；保存端 `persistScriptRef` 遇跨宿主匿名脚本改为复制兜底 | 已修复 |

### C. 画布与编辑体验（7 个）

| # | 缺陷 | 现象 | 根因 | 修法 | 状态 |
| --- | --- | --- | --- | --- | --- |

## 三、教训（写给自己）

1. 文档承诺的语义必须能经得起逐行核对——#3 的「真实并发受预算封顶」直到用户问起才暴露是假的。
2. 「递归 + 末尾清理」的组合是数据丢失温床（#7）：清理的 `seen` 集合必须与最终落库内容同源。
3. jsonb 不保键序，客户端任何「从数据库读回再重建对象」的地方都会让 `JSON.stringify` 比较失真（#16），
   比较类逻辑一律走稳定序列化。
4. 画布上「点击 vs 拖拽」一律用 React Flow 生命周期 + 位移阈值区分，不要写自己的鼠标位移判定（#14/15）。

## 四、多轮用户反馈修正

### 第二轮用户反馈修正

- **并发请求的单步调试**原先走 `enqueueRun` 只发一个请求，完全忽略 `concurrency`。改为
  并发 > 1 时走容器路径（`runGraph` 写容器行 + N 个子步骤行 + N 条 HTTP 记录），请求抽屉
  按容器结果渲染「N 次请求通过」摘要与逐条证据。
- 曾观察到单步调试**一直排队中**：查证为 `tsx watch` 在我改文件期间反复重启 worker，
  job 在 active 态被杀（队列现已空，同一分钟后的执行由新 worker 正常完成）；回收扫描
  会把这类无主行标成 failed。不是并发功能的缺陷，但说明**改完必须重启 worker**。
- 循环容器从「面板 + mini-card 只读列表」返工为**真正的画布嵌套容器**（可拖入已有步骤、
  可拖出、框内步骤双击直接编辑），并把成员关系的唯一编辑入口收敛到画布；抽屉里只做只读
  回显与循环参数，去掉了第二套增删。
- 后端补上 `MAX_LOOP_BODY_NODES` 的实际校验（此前定义了没用上，前端显示 /10 而后端按 50 放行）。

### 第三轮用户反馈修正

- **单步调试漏了脚本内联**（`pre-request hook "ss" failed: hook script content is missing`）：
  `executeGenericStep` 只调了 `prepareFlowNodes`，而钩子/断言/后置脚本的正文内联在
  `inlineFlowNodeScripts` 里。完整运行入队时调了它，单步调试没调，于是引用公共脚本的钩子
  在这条路径上只有 id 没有正文。改为先统一 `inlineFlowNodeScripts` 再 `prepareFlowNodes`，
  两条路径共用同一套内联；顺带删掉各分支里那几处零散的内联调用。
- **拖动后位置回弹**：画布位置原先只存在 React Flow 的 `nodes` state 里，而投影 effect 依赖
  `order`/`stages`/`nodeStatus`——添加步骤会触发重新取计划，effect 重跑就用文档里的旧坐标
  重建节点。改为拖拽结束即把位置写回文档（`foldPositions`），文档成为位置的唯一真源。
- **多选拖动**：新增画布模式切换按钮（框选/平移）。框选下左键拖拽画选择框、中键与右键
  仍可平移，Shift/⌘ 点选也能加选；选中的多个步骤原生整组拖动，落库由同一个
  `onNodeDragStop` 处理（支持多节点，逐个判定是否进出循环框）。
- **撤销/重做**：新增 ⌘Z / ⇧⌘Z 与工具栏按钮。历史记的是**文档快照**（名称、环境、步骤树、
  连线、变量）而不是画布投影；快照在每个离散动作之前入栈（加/删/连/删连/拖动），抽屉与
  变量面板在打开时取基线、关闭时若有变化才入栈——否则每敲一个字符都会进历史，撤销一次只
  退一个字母。输入框与 Monaco 内的 ⌘Z 交还给它们自己（脚本编辑器有自己的编辑历史）。
  同一事件里的重复入栈会被去重（删节点会同时产生删连线，两次拿到的都是同一份「删之前」）。

### 第四轮用户反馈修正

- **画布一直闪动**（重渲染死循环，我自己引入的）：`materialize()` 依赖 React Flow 的
  `nodes`，而计划 effect 依赖 `materialize` → 投影 `setNodes` → `nodes` 变 → 重新取计划 →
  `order`/`stages` 换新数组 → 投影再跑，无限循环。位置既然已经在拖拽结束时落回 `steps`，
  文档计算就不该再看画布状态：改名为 `documentNow()`，只依赖 `steps` + `edges`。另外计划
  结果内容未变时保持原数组，省掉每次编辑后多余的一次整图重建。
- **框选不起作用**：两个原因。一是投影重建时丢掉了 `selected`（选中属于画布不属于文档），
  现在从上一份节点里带过来；二是 `onNodeClick` 单击就打开抽屉，框选时每点一个就弹一次抽屉，
  改为只在平移模式下单击打开、框选模式用双击。框选判定同时放宽为 `SelectionMode.Partial`
  （碰到即选中，要求完全框住会让人反复重画）。
- **循环内条件节点被框线压住**：`loopSize` 对所有卡片按同一高度估算包围盒，而条件节点底部
  多一行真/假出口，框算矮了卡片就溢出到框外。改为按类型给足高度余量（条件最高），新步骤
  入框时也按实际高度堆叠。
- 顺带补一个语义漏洞：体内没连线时执行器会生成默认顺序链，但从条件节点出去的默认边无法
  推断走哪个分支、会按「成功」放行使条件静默失效。现在默认链跳过条件节点的出边，且保存时
  要求「体内有条件节点必须显式连线」。

### 第五轮用户反馈修正（其中两条是我引入的严重缺陷）

- **⚠️ 保存流程会删掉该流程的内联脚本**：我让 `persistFlowScripts` 对循环体递归调用自己，
  而它末尾会 `collectGarbage`——那次清理拿着只含体内脚本 id 的 `seen`，把顶层节点引用的
  内联脚本（`name IS NULL`）全当垃圾删了，于是再保存就报
  `referenced script does not exist in this project`。改为遍历与清理分离：内部 `walk`
  只持久化并累加同一份 `seen`，`collectGarbage` 只在最外层执行一次。
  **损坏范围**：仅该流程节点上**直接写的**断言/钩子/后置脚本（匿名）；脚本库里的公共
  脚本（有名字）不受影响，需要重新指认引用。
- **⚠️ 并发请求永远停在「执行中」**：并发 worker 的 `for(;;)` 只在失败或取消时退出，漏了
  「领到的下标超出并发数就收工」，于是无休止地自增下标继续发请求，直到流程超时。补上边界。
- **只是点选/框选也提示需要保存**：拖拽结束时无条件把位置写回文档，而 React Flow 对
  「点一下节点」也会走一遍 dragStart/dragStop。改为只在坐标真的变化时才写文档、才进历史。
  （真的移动了仍然会标脏——位置是要保存的文档内容。）
- **循环内两个分支步骤无法并排**：框的最小宽度只够放一张卡，把第二张卡拖到右边时它的中心
  落在框外，于是被判定为「移出循环」。改为最小宽度按并排两张卡计算，并给容器加上
  `NodeResizer`——尺寸存进 `LoopFlowNode.size`，因为对容器来说尺寸决定它能框住多少，
  和 `position` 一样属于文档。
- **右键框选**：按要求不做。改为把「Shift + 左键拖拽框选」写进画布提示与模式按钮的
  tooltip（React Flow 的 `selectionOnDrag` 只认左键，右键框选需要自绘选框）。
- **出口圆点：点一下加一步，按住拖是连线**：用 React Flow 的连接生命周期加一个位移阈值
  区分（`ADD_STEP_DRAG_THRESHOLD = 6px`，因为 React Flow 从 mousedown 起就在做连线交互，
  两者只能靠位移分辨；阈值为 0 会把手抖误判成拖拽）。**点一下**（位移小于阈值且没连上任何
  目标）= 打开节点选择器，新步骤摆在来源节点下方并自动连上（来源是条件节点时按点的是哪个
  出口带上真/假分支，落在与来源相同的作用域）；**拖动**只用于连线，拖到空白处松手什么都
  不做——那是一次没连成的连线，不该凭空落一个节点。
  另外圆点上的点击不再触发 `onNodeClick`：否则节点抽屉会盖在节点选择器上面，表现为
  「点圆点变成打开抽屉」。

**数据修复**：用户选择不修复。流程「测试」的 5 处脚本引用仍指向已删除的行（其中 `ss`
前置钩子的正文可从 `executions.run_spec` 捞回，其余 4 处无源），保存时会持续报
`referenced script does not exist in this project`，需要在界面上重新指认或删除这些引用。

### 第六轮用户反馈修正

- **点圆点加一步没反应**：判定原先挂在 `onConnectStart/onConnectEnd` 上，而 React Flow 的
  `connectOnClick` 默认开启会把圆点上的**单击**吞成「点击连线」的第一步，`onConnectEnd`
  根本不触发。改为不依赖那两个回调：新增 `SourceHandle`，在圆点自身的 pointer 事件上比较
  按下与松开的位移（阈值 6px，手抖不算拖拽），没移动就当点击、走「加一步」；同时
  `connectOnClick={false}`。另外圆点上的点击不再冒泡成 `onNodeClick`——否则节点抽屉会盖在
  节点选择器上面，表现为「点圆点变成打开抽屉」。**拖动只用于连线**，拖到空白处不生节点。
- **用例导入流程节点后保存报「是否公共脚本」**：用例的钩子/后置脚本多是**用例私有的匿名
  脚本**（`owner_case_id`），而 `node-source` 把引用原样交给流程节点，保存时
  `persistScriptRef` 拒绝跟随别的宿主的匿名脚本（那一行随用例一起删，跟随会把两个宿主绑在
  一条随时消失的行上）。按计划 4.0.1 的 follow / copy 补齐 copy 支：
  1. 导入时接手（新增 `adoptScriptRef` / `adoptScriptRefs`）——公共脚本保持跟随，匿名脚本
     改成携带正文与依赖的「新脚本」形状，流程保存时建自己的一份，编辑器里当场就能看到正文。
  2. 保存时兜底——`persistScriptRef` 遇到别的宿主的匿名脚本改为复制而非抛错，让导入更早、
     已经带着别人 id 的旧节点也能存下去。用户没做错任何事，不该在保存时被要求「先存成公共
     脚本」。

### 第七轮用户反馈修正

- **循环节点没有删除按钮**：`.flow-node-delete` 默认 `opacity: 0`，只由 `.flow-node:hover`
  揭示，而循环容器的根类是 `.flow-loop`，所以那个按钮永远不显形。补上
  `.flow-loop:hover` 选择器。
- **⚠️ 并发请求的令牌记账是假的**（自查发现，与文档承诺矛盾）：令牌只按「节点」计数，
  而并发请求节点扇出的 N 个子请求不各占令牌。于是「循环并发 2 × 请求并发 10」会有 20 个
  请求同时在飞，而池子只记了 2 个——文档里写的「真实并发受整次执行预算封顶」根本不成立。
  改为：并发请求节点自身**不取**令牌（它不发请求，只扇出），**每个在飞的子请求各取一个**。
  这样不变式恢复为「每个在飞的 HTTP 请求恰好持有一个令牌」，声明的并发是形状，预算不够时
  自然分批发出。
- **加了循环节点后永久显示「未保存」**（脏标记误判，循环确实已存库）：基线来自服务端返回的
  文档，而 `flows.nodes` 是 **jsonb**——jsonb 不保留键的插入顺序（`{nodes, edges}` 存进去
  读出来是 `{edges, nodes}`），而客户端 `splitEdges` 重建 body 时写的是 `{nodes, edges}`。
  `snapshot()` 用 `JSON.stringify` 按插入顺序序列化，两串永远不等。改为 `stableJson()`
  深度按键名排序后再序列化——脏检查要比较**内容**而不是键顺序。这类问题只要有一处客户端
  重建对象就会复发，所以修在比较函数上而不是逐个对齐键序。

## 五、循环 + 请求并发的执行语义

（回答「循环 5 次 / 循环并发 2 / 体内请求并发 2」）

- 迭代调度是**滑动窗口**而非固定批次：2 个 worker 从 1..5 的队列里轮流领号，谁先跑完谁领
  下一个。总量与「分批 1,2 → 3,4 → 5」相同，区别是快慢不均时窗口不空等——一个慢迭代不会
  卡住另一条。
- 总请求数 = 5 × 2 = 10；同时在飞的 HTTP = min(2 迭代 × 2 请求, `FLOW_PARALLELISM`)。
- 达到预算不报错，只是排队分批发出。要真拿到 10 并发需把 `FLOW_PARALLELISM` 提到 10（上限 10）。
- 无死锁：令牌只被「真正在做事的叶子/子请求」持有，它们都会结束并释放；容器与扇出节点不持
  令牌，所以不存在持有者互等的环。循环的局部信号量只被迭代 worker 持有，而叶子从不等信号量。
- 代价：每个子请求都会写一条 `executions` + 一行嵌套步骤，10 次并发就是 10 条记录。这也是
  它不能当压测设施用的原因。
