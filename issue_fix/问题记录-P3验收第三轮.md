# P3 验收缺陷（第三轮）

用户手动验收 P3 套件页时反馈的问题。前两项为界面缺陷，第三项为布局调整，
第四项为手动触发的能力缺口（变量覆盖）与优先级确认，第五项为同机制文案口径统一。

## 1. 成员相关列表仍有未分页的

- **现象**：运行抽屉（点「运行」或「查看成员」弹出的抽屉）把一次运行的全部成员行
  一次铺开；「添加成员」选择器的流程 tab 也不分页（用例 tab 上一轮之前就有分页）。
  成员多的套件在两处都拉成一条长列表。
- **根因**：上一轮只给套件配置页的两处清单（手动成员列表、解析预览）做了分页，
  运行抽屉与选择器漏掉了；报告详情的成员明细按边界 14 有意不分页（通读「哪几个
  失败了」不该翻页），维持原决策。
- **修法**：运行抽屉成员行就地分页（每页 20，与配置页清单同一个页大小；换一次运行
  回到第一页并收起展开行）；选择器流程 tab 就地分页（流程接口本就整份返回，分页
  只属于展示层；与用例 tab 同页大小，切 tab/搜索回到第一页）。
- **状态**：已修复。

## 2. 定时调度空态是整张卡片

- **现象**：套件页「定时调度」面板没有调度时，显示一张带标题、说明和「新建调度」
  按钮的空态卡片，把页面拉长且与表头抢视觉。
- **根因**：空态复用了通用的 `Empty` 组件（面向整页「从零开始」的场景）；而调度面板
  的新建按钮常驻在面板头上，空态卡片里的动作是重复的。
- **修法**：空态改成表内一行「暂无数据」（新键 `common.noData`）；删除不再使用的
  `schedules.emptyTitle` / `schedules.emptyHint` 两键。
- **状态**：已修复。

## 3. 定时调度与通知设置卡片位置

- **现象/诉求**：通知设置卡片排在定时调度之前，阅读顺序与执行顺序相反。
- **修法**：两卡片互换——定时调度在前（「怎么跑」），通知设置在后（「跑完之后」）。
- **状态**：已调整。

## 4. 手动运行套件没有变量覆盖入口

- **现象**：调度与 Webhook（含 CI 场景）触发套件时都能带变量覆盖（泳道入参），
  手动点「运行」却发不了 `variables`——同一个执行 API 的三种触发源有两种能力。
  手动想把一次回归统一打到某条泳道时没有入口。
- **根因**：后端 `POST /test-suites/:suiteId/execute` 早已接受 `variables`（P3-3 统一
  触发路径），前端 `executeSuite` 也带了这个参数，唯独套件页的「运行」按钮没有
  任何输入界面。
- **修法**：「运行」改为先弹确认窗（与接口页批量调试同一模式）：变量覆盖
  （KeyValueEditor，键约束与服务端同一条 `^[A-Za-z_][A-Za-z0-9_]*$`）、提示文案
  说明优先级与「不要放密钥」，确认后随执行入队。覆盖是**每次运行的入参**而不是
  套件配置：不落库，值在页面会话内保留（连续打同一泳道不必重敲）。
- **状态**：已实现。

## 5. 变量覆盖相关文案口径不一致

- **现象**：同一条泳道机制在三处提示里说法不同。运行弹窗写「优先级 套件 > 流程 >
  环境」——但同一句又说「不保存进套件」，层名自相矛盾（覆盖是触发入参，不是套件
  配置）；环境默认头提示写「由触发时的变量覆盖切换泳道」，没给优先级链；调度编辑
  写「最高优先级」。三处读起来像三种机制。
- **根因**：第 4 项新增运行弹窗文案时临时造了「套件」这个层名，没有对齐既有两处
  的「触发时的变量覆盖」叫法。
- **修法**：三处统一为同一层名与同一条链——「触发时的变量覆盖 > 流程种子变量 >
  环境变量」（`suites.runVariablesHint` / `schedules.variablesHint` /
  `environments.defaultHeadersHint`，双语各三处）；默认头提示补上链，调度提示
  用「与手动运行相同」互相锚定，运行弹窗提示用「与调度 / Webhook 触发相同」。
- **状态**：已修复。

## 6. 变量覆盖编辑器样式与请求头/参数编辑器混用

- **现象**：运行弹窗与调度编辑里的变量覆盖用的是 `KeyValueEditor`（表 / 文本双
  模式切换 + 每行启用勾选）——那是为请求头/参数调试设计的控件。用户期望与环境
  管理里普通变量行（列头「变量名/变量值」+ 键/值/复制/删除）一致。
- **根因**：第 4 项补运行弹窗时直接复用了现成的 `KeyValueEditor`，只顾了功能没对
  齐样式语义：变量覆盖没有「临时停用一行」「从 curl 批量粘贴」这两个动作，模式
  切换与勾选列在这里是噪音。
- **修法**：新增 `VariableRowsEditor`（环境抽屉普通变量行的同款排版：列头 +
  `minmax(0,1fr) minmax(0,1.4fr)` 的键值行 + 复制 `{{key}}` + 删除，末尾常驻空行），
  运行弹窗与调度编辑两处换用。不做 Text/Secret 切换——触发参数里不许放密钥
  （边界 17）。新增 `common.variableName` / `common.variableValue` 两键（双语各 +2）。
- **状态**：已修复。

### 附：变量替换优先级（代码现状确认，与用户理解一致）

```
触发时的变量覆盖（手动运行弹窗 / 调度 / Webhook·CI）
  > 流程种子变量（flow.variables）
    > 环境变量（单接口/用例依赖的那一层；环境默认头 {{lane}} 在这里解析）
```

- 用例成员：触发覆盖作为 `RunSpec.variables` 垫在环境变量之上
  （`lib/run.ts` `performRun`）。
- 流程成员：`{ ...flow.variables, ...overrides }` 冻进流程执行
  （`lib/suiteRun.ts` `runFlowMember`），再在 `lib/flowRun.ts` 里压过环境变量。
- 单接口/用例没有自己的变量袋，它们引用的就是环境层——所以「套件 > 流程 >
  单接口/用例」即上面这条链。CI/CD 走 Webhook 触发（HMAC），`variables` 一直是
  同一条通道，无需另改。

## 附：修复验证约定

按项目约定未做自动化/浏览器验证，行为验收由用户手动进行（重启服务后走查：
运行抽屉与添加成员弹窗的分页、调度空态、卡片顺序、运行弹窗带 lane 覆盖跑一次
并核对报告标识段显示 `lane=...`；三处变量覆盖提示文案口径一致；两处变量覆盖
编辑器为环境变量行样式）。
