# 问题记录 — P4.5-13 执行详情页四处前端缺陷

> 发现时间：2026-09-01（P4.5-11 落地时顺手体检发现）
> 涉及：`apitest-web/src/components/PipelineRunPage.tsx`、`apitest-web/src/design-system.css`
> 状态：**全部已修**（已随 2026-09-03 P4.5 用户验收通过关闭）

四处都属同一类：**类型系统或 CSS 变量表挡不住的静默失效**——页面照样渲染，
只是某个东西不生效，而不生效的样子和「设计如此」分不开。P4.5-13 落地当轮
`pnpm check` 没编过（`Empty` 与 `RefObject` 两处会报错），说明那一批的前端改动
没有跑过类型检查。

## 缺陷一：`Tip` 的 prop 名写错，两处提示永不出现

**现象**：用例列表里「有失败信息」那一格、报告视图里的附件回形针图标，
悬停没有任何提示。

**根因**：`ui.tsx:17` 的 `Tip` 接受的是 `text`，两处调用写的是 `content`：

```tsx
<Tip content={row.message}>…</Tip>
```

`Tip` 的实现是「`text` 为空时直接透传 children」（那是为「没有内容就不要包一层」
设计的），于是 `text` 恒为 `undefined` ⇒ 恒走透传分支 ⇒ 提示永不渲染，且**不报错、
不留痕**。TypeScript 本该拦住这个（多传的 `content` 是超额属性），P4.5-13 那轮没跑
`pnpm check`。

**修法**：两处 `content=` 改 `text=`。

## 缺陷二：`Empty` 缺必填 `title`，五处空态渲染出空标题

**现象**：日志 / 用例 / 报告 / 产物四个 tab 的空态只有一行说明文字，上方标题位是空的。

**根因**：`Empty` 的签名是 `{ title: string; hint: string; action? }`，五处只传了
`hint`。这是一个真正的类型错误（`pnpm check` 会报 TS2741），同样因为那轮没跑检查
而漏了。

**修法**：五处补 `title`，i18n 各补一个 `*EmptyTitle` 键（zh/en 双份）。空态标题
说「没有什么」，`hint` 说「为什么没有 / 下一步」，与其它页的空态同款分工。

## 缺陷三：状态色用了不存在的类名，run 状态恒为无色

**现象**：执行详情页概要行的状态文字（成功 / 失败 / 执行中）没有颜色，只有一个
黑色圆点。

**根因**：

```tsx
<span className={`status status-${status}`}>
```

设计系统的状态色是**属性选择器**（`design-system.css:617`：
`.status[data-status="pass"]`），`.status-pass` 这个类从来不存在。于是
`--pass/--fail/--busy` 一个都没命中，那一行退化成继承色。`running` 的呼吸点动画
（全 app 唯一一处 ambient 动画）也一起失效。

**修法**：改成 `<span className="status" data-status={status}>`。同款写法在
`RepoOnboarding.tsx` 与 `RunnerPoolPanel.tsx` 里都是对的，只有这一处走偏。

## 缺陷四：CSS 里两个从未定义的 token

**现象**：日志框、timeline 容器、报告附件图片三处应有的圆角是直角；趋势页的网格线、
空桶基线、环形图底环三处应有的浅色线是黑色（继承 `currentColor`）。

**根因**：

- `var(--radius)` 三处（`design-system.css` 的 `.pipeline-log` / `.timeline-wrap` /
  `.attachment-image`）——token 表里只有 `--r-sm` / `--r` / `--r-lg`；
- `var(--rule)` 三处（`Trends.tsx` 的 `stroke` / `fill`）——token 表里只有 `--line`。

CSS 自定义属性解析不到时**静默失效**，不报错、不告警，而 `border-radius: ;`
的效果与「没写这一行」完全一样，所以能一直躺着。`--rule` 是 P3 趋势页留下的，
`--radius` 是 P4.5-13 留下的，两者同一类问题，一起改。

**修法**：`var(--radius)` → `var(--r)`（5px，与卡片/输入框同族）；
`var(--rule)` → `var(--line)`。

## 教训

设计系统的 token 与原语签名是**契约**，但 CSS 变量那一半没有编译器守着。
新增 CSS 时引用的每个 `var(--x)` 都要在 `design-system.css` 的 token 段里能找到；
组件那一半有编译器守着，前提是**改完要真的跑 `pnpm check`**——本轮四条里有两条
是 tsc 早就能报出来的。
