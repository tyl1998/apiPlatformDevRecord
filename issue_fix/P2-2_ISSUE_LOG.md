## #1 脚本节点保存报「a script node needs a script」

**发现阶段**：用户反馈（新建脚本节点并写入代码后保存流程）。

**现象**：编辑器里已经写了脚本，保存流程仍报 `a script node needs a script`。

**根因**：新建脚本节点时，Monaco 只是**显示**默认模板兜底，模板并未写入 `script.content`。
保存时后端拿到的是没有 content 的引用，按「脚本节点必须有正文」校验拒绝。

**修法**：
- 创建节点时即写入 `DEFAULT_SCRIPT_NODE_TEMPLATE` 到 `script.content`
- 存量空节点打开时自动补齐草稿（`content` 为 undefined 时补一次默认正文）

**状态**：已修复

---

## #2 「存为公共脚本」按钮不可点击 / 读取不到公共脚本

**发现阶段**：用户反馈（脚本节点抽屉）。

**现象**：
1. 脚本节点写入了脚本，但「存为公共脚本」按钮灰置不可点。
2. 公共脚本下拉显示为空，无任何提示。

**根因**：
- 与 #1 同源：真实 `script.content` 为空，发布按钮按 `!content.trim()` 禁用。
- 公共脚本列表请求失败时静默清空列表，不提示，看起来像"没有公共脚本"。

**修法**：
- 随 #1 修复后按钮恢复可用。
- 脚本节点公共脚本加载失败时清空两组缓存并 `message.error` 提示，不再静默。

**状态**：已修复

## #3 条件节点只有单一出口，if/else 走向不清晰

**发现阶段**：用户反馈（条件节点设计）。

**现象**：条件节点只有一个无语义的 source 出口，连出来的线看不出是「条件成立」还是
「条件不成立」走哪条。

**根因**：条件节点初版只有一个 Handle，连线不携带分支语义（`FlowEdge.on` 未从连线写入）。

**修法**：
- 条件节点改为两个显式出口：「满足」（左）/「不满足」（右），画布边显示分支标签
- 连线时按 `sourceHandle` 持久化 `on: true / false`
- 加载旧图时按 `edge.on` 还原 `sourceHandle`，保证新旧数据一致
- 抽屉内补充两个出口的说明

**状态**：已修复

## #4 脚本节点编辑保存后重新打开仍是旧正文

**发现阶段**：用户反馈（脚本节点保存后重开）。

**现象**：保存脚本后关闭抽屉再打开，编辑器显示的仍是旧内容，需要刷新页面才能看到刚保存的正文。

**根因**：保存流程时，服务端把内联正文持久化到匿名脚本行并把节点规范化为 `{ scriptId }`
（`content` 从字符串变为 undefined）。抽屉只在 `scriptId` 变化时重新拉取，未监听
`content: string → undefined` 这一保存边界，继续命中旧的 `resolved` 缓存。

**修法**：`resolved` 拉取 effect 增加 `node.script.content` 依赖：编辑期间（content 有值）直接
跳过拉取；保存后 content 消失即清缓存并重新读取服务端正文。

**状态**：已修复

## #5 脚本输入框识别不到空格键

**发现阶段**：用户反馈（脚本节点 Monaco 编辑器）。

**现象**：在脚本编辑器里按空格没有任何输入。

**根因**：React Flow 默认把 `Space` 注册为全局「临时平移画布」快捷键（`panActivationKeyCode`），
Monaco 的隐藏 textarea 未被识别为常规输入目标，空格被监听器截获。

**修法**：画布已有拖拽平移，本页禁用该冗余快捷键（`panActivationKeyCode={null}`）。

**状态**：已修复

## #6 数据库节点单步调试实际不可用（P2-1 遗留）

**发现阶段**：P2-2 联调（数据库节点抽屉「运行」）。

**现象**：数据库节点点「运行」后端返回 400，无法调试；即便绕过，返回结果形状与前端期望不符。

**根因**：
- 前端 `executeFlowNode` 调 `/nodes/execute`，后端该路由此前对非 request 节点一律返回
  `database nodes use /nodes/execute-step`，而前端从未调用 `/nodes/execute-step`。
- 前端 `ExecutionStep` 期望 `type` 字段，后端 `mapExecutionStep` 返回的是 `stepType`，形状不一致。

**修法**：
- `/nodes/execute` 改为按节点类型分派：request 走 `enqueueRun`（HTTP 执行），
  database/script/condition 走统一的 `executeGenericStep`（通用步骤证据）
- 保留 `/nodes/execute-step` 兼容路由
- 统一通用步骤模型（`stepType / stepId / stage / output / error`），前端类型同步对齐
- `/nodes/executions` 合并返回 HTTP `executions` 与通用 `execution_steps` 两类证据

**状态**：已修复

## #7 脚本断言/前置脚本 try-run 与流程执行未携带依赖库

**发现阶段**：脚本库补全功能联调。

**现象**：在脚本里声明了依赖库的函数（补全能提示），但 try-run 或流程执行时该函数 `undefined`。

**根因**：`tryScript` 与入队内联（`inlineScriptContent / inlineHookContent / inlineScriptNode`）
未把当前未保存的 `dependencies` 选择传给运行侧；服务端只按已持久化的 `script_deps` 组装库正文。

**修法**：三处内联均支持请求携带的 `dependencies` 覆盖——无 `scriptId` 的私有草稿按
`dependencies` 加载库正文；有 `scriptId` 时请求携带的依赖优先于数据库已存依赖，保证
「补全提示得到」与「运行得到」一致。

**状态**：已修复

## #8 跟随公共脚本「脱离」后丢失依赖库

**发现阶段**：脚本库补全功能联调。

**现象**：跟随公共脚本后点「脱离为私有」，依赖库选择清空，原公共脚本声明的库全部丢失。

**根因**：detach 只复制 `content`，未复制 `dependencies`。

**修法**：断言、前置、脚本节点三处 detach 均同时复制 `referenced.dependencies`。

**状态**：已修复

## #9 公共脚本保存失败无具体错误

**发现阶段**：脚本库契约校验落地后。

**现象**：公共脚本保存失败时只显示通用「保存失败」，看不到服务端返回的具体原因
（如脚本库契约违规的详细文案）。

**根因**：`PublicScripts.save()` 只取 HTTP status，丢弃 `response.data.message`。

**修法**：优先展示服务端 `response.data.message`，无详情时回退通用文案。

**状态**：已修复

## #10 断言脚本下拉暴露所有 kind 的公共脚本

**发现阶段**：脚本智能补全功能改造。

**现象**：断言脚本编辑器里可选择 hook/library/node 类型的公共脚本，选错类型后运行时行为与
预期不符（如把库脚本当断言用）。

**根因**：断言编辑器把 `api.scripts()` 全量结果直接作为选项，未按 `kind` 过滤。

**修法**：下拉仅列出 `kind=assertion` 的公共脚本；依赖库选择单独列出 `kind=library`。

**状态**：已修复

---

## #11 并行加载失败时只清空一半缓存

**发现阶段**：脚本节点依赖选择器联调。

**现象**：公共脚本与脚本库并行请求中一个失败，页面保留另一组旧数据，可能出现跨项目残留。

**根因**：两处 `api.scripts()` 各自独立 catch，失败时只清空自己那组。

**修法**：`Promise.all` 合并加载，任一侧失败即同时清空两组并提示。

**状态**：已修复

## #12 条件节点只支持单条件，无法表达与/或

**发现阶段**：用户反馈（条件节点功能范围）。

**现象**：条件节点只能配置一条 `variable / operator / value`，无法表达「A 且 B」「A 或 B」。

**根因**：数据模型与 UI 均为单条规则。

**修法**：
- 模型扩展为扁平条件组：`{ mode: "all" | "any", rules: [] }`，最多 20 条
- 后端 `evaluateConditionGroup` 按 AND/OR 汇总，执行证据逐条记录变量/操作符/期望值/实际值/结论
- 历史单条件 JSON 在 `mapFlow`/`toFlowNode` 边界自动归一为单条 AND，无需迁移
- UI 支持增删规则与模式切换

**状态**：已修复

---

## #13 空输入触发补全时没有 ctx 入口

**发现阶段**：脚本智能补全功能联调。

**现象**：Ctrl+Space 触发补全（输入为空）时看不到任何 ctx 成员，容易误以为没有内置上下文。

**根因**：补全过滤逻辑把空串匹配过滤掉。

**修法**：输入为空时返回全部符号（含 `ctx` 根与全部 ctx 成员），带前缀时只返回匹配项。

**状态**：已修复
